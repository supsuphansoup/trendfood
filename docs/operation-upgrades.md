# 탐색·요리 기능과 연결할 계정

2026-11-20 사용자가 순차 적용을 요청한 운영 개선이다. 공개 JSON 모드와 정적 내보내기를 유지한다.

## 자동화

- 일일 실행은 기존 매일 10:17 KST, 검색·사진·원고 한도를 유지한다. 추천 순환이나 사진 교체로 테스트가 다른 음식을 집는 문제를 고쳤다.
- 정규 수집·배포 실패 시 `자동 음식 수집·배포 실패` GitHub 이슈 하나를 만들거나 갱신하고 다음 정상 실행에서 닫는다. 알림 메일·앱 수신 여부는 저장소 Watch/개인 GitHub 알림 설정에 따른다. 별도 이메일 전송은 설정하지 않았다.
- Actions → pipeline → Run workflow → `checks_only=true`는 수집·사진 검색·유료 AI 호출 없이 현재 콘텐츠와 전체 검사를 실행한다. 이 모드의 성공을 수집 복구로 알리지 않는다.
- 새 음식의 사진·근거·검사 조건은 그대로다. 기존 음식 추천 순환은 새 유행 발견이 아니다.

## 첫 공개일과 최근 발견

- `publishedAt`은 서비스 첫 공개일이다. 자동 게시가 사진 검사까지 통과했을 때 기록하고 원고 갱신 시 보존한다. 원문 확인일·추천 갱신일·유행 시작일과 다르다.
- 최근 발견은 빌드 날짜 기준 30일 미만이다. 기존 음식에 추정 공개일을 채우지 않아 첫 적용 때 모음이 비어 있을 수 있다. 일일 정적 배포 때 갱신된다.

## 방문 통계 연결 — 현재 ID 없음

1. Google Analytics에서 이 사이트의 GA4 웹 데이터 스트림을 만든다. 브라우저 연결 오류로 계정 생성·연결은 수행하지 못했다.
2. 데이터 스트림의 **향상된 측정은 끈다**. 이 구현은 직접 이벤트를 보내므로 자동 페이지 전환·사이트 검색·외부 링크 이벤트를 켜면 중복 집계나 URL 검색 조건 전송이 생길 수 있다.
3. 저장소 Settings → Secrets and variables → Actions → Variables에 `NEXT_PUBLIC_GA_MEASUREMENT_ID=G-…`를 넣고 deploy를 실행한다. ID는 공개 식별자다. 로그인 정보·비밀 키를 코드에 넣지 않는다.
4. 사이트 하단에서 통계 허용 후 GA4 실시간 보고서에서 확인한다. 미허용 상태에서는 Google 태그를 불러오지 않으며, 관리자 화면은 수집하지 않는다. 취소하면 이후 전송을 중지하고 사이트의 GA 쿠키를 지운다.
5. 이벤트: `page_view`, `search`(원문 대신 `redacted`와 검색어 길이), `select_content`(음식 주소), `food_like`(찜·해제), `purchase_click`(음식 주소·일반/제휴 구분). 구매 클릭은 실제 결제가 아니다. 필요한 사용자 정의 측정기준은 GA4 관리 화면에서 등록한다.

현재 측정 ID가 없어 운영 방문 통계를 집계하지 않는다. 자동 브라우저 검사는 가짜 측정 ID·네트워크 응답으로 동의·이벤트 차단·검색어 비전송을 확인하며 실제 GA4 수신 검증을 대신하지 않는다.

## 검색엔진 연결 — 소유권 확인 대기

- `/sitemap.xml`, `/robots.txt`, 각 공개 페이지 canonical, 음식 공유 메타데이터를 정적으로 제공한다. 관리자·검색 조건 주소는 사이트맵에서 제외한다.
- 실제 레시피에만 Recipe JSON-LD를 제공한다. 완제품·음식 소개에 레시피나 가짜 평점을 만들지 않는다. 별도 대기 시간이 있는 원문의 전체 시간을 조리 시간으로 추정하지 않는다.
- Search Console에서 URL 접두어 `https://trendfood.pages.dev/`를 추가한다. HTML 태그 확인 값만 저장소 변수 `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`에 넣고 재배포 → 소유권 확인 → `sitemap.xml` 제출 순서다. 현재 확인 값과 계정 연결이 없어 등록·색인 완료로 보고하지 않는다.
- 네이버 서치어드바이저 등록도 계정·소유권 확인이 필요하다. 이번에 임의 토큰이나 등록 완료 기록을 만들지 않았다.

## 보유 재료·분량·요리 모드

- 보유 재료로 찾기는 레시피만 부족한 재료 수가 적은 순서로 보여준다. 이름은 상세 체크리스트와 같은 정확한 키를 쓰며 부분 일치로 다른 재료를 보유 처리하지 않는다. 기본 양념은 레시피별 기본값으로 시작한다. 같은 재료의 기본값이 다르면 선택란에 중간 상태로 표시하며, 직접 선택한 상태는 모든 레시피에서 기본값보다 우선한다. 보유 목록 자체는 브라우저에만 저장하고 공유 URL에는 탐색 모드 여부만 넣는다.
- 분량은 0.5·1·2배이며 기본 분량이 정확한 인분이면 인분으로 표시한다. 숫자·분수·범위와 명확한 단위만 계산한다. 복합 사용량은 원문을 보존하고 별도로 알린다. 구매 포장·상품 주소·단계의 수치·조리 시간은 바꾸지 않는다.
- 요리 모드는 큰 단계·완료 체크·타이머를 제공한다. 완료 상태는 현재 단계 원문 기준으로 브라우저에 저장한다. 타이머는 실제 경과 시간을 반영하며 모드를 닫으면 해당 모드의 타이머는 종료한다.
- 화면 켜두기는 사용자가 켰을 때만 요청한다. 미지원·권한 거절을 안내하고 모드 종료·화면 숨김 시 해제한다. 화면으로 돌아오면 다시 요청한다. 기기·브라우저가 요청을 거부할 수 있다.
- 저장 공간을 사용할 수 없으면 같은 페이지 안에서 선택 상태를 유지한다. 새로고침 후 보존은 보장할 수 없다.
