# 원본 영상 ID 저장과 YouTube 공식 임베드

- 날짜: 2026-11-10
- 누가: codex (AI 도구: Codex)
- 관련: docs/plan.md 3단계 / docs/spec.md R5 / 커밋 없음(지시서에서 금지)

## 한 것
- 운영자가 입력한 공식 YouTube 주소를 검증해 11자 ID만 저장하고, 입력을 비우면 영상을 내리도록 했다. 저장 요청은 `video_id` 열 하나만 포함한다.
- 상세 화면의 임시 재생 버튼을 공식 `youtube-nocookie.com` iframe과 출처 링크로 바꿨다. 영상이 없으면 구역을 숨기고 설명 폭을 제한하며, 관련 영상 개수 표기는 없앴다.
- DB 열이 없어도 공개 데이터 변환과 관리자 목록 조회가 동작하고, 관리자 영상 구역에는 SQL 실행 안내만 보이도록 했다.
- 트랜잭션으로 묶은 반복 실행 가능 마이그레이션과 예시 SQL을 만들고, 개인정보 안내·설정 순서·진행 문서를 갱신했다.

## 정한 것·남은 것

- 감독자 승인(`msg_d40502a639f1`): 390px 화면에서 좌우 20px 여백·16:9 기준을 유지하면 높이가 약 197px가 되므로 `aspect-video`에 `min-h-[200px]`를 추가했다. iframe 실제 크기가 가로·세로 200px 이상인지 두 폭 모두 검사한다.
- 임의로 넓힌 작업 범위·새 패키지·허용 목록 밖 타입 수정은 없다. 커밋·push·브랜치 생성·stash·reset·파일 삭제·실제 Supabase 및 YouTube 호출은 하지 않았다.
- **SQL은 이 실행 환경에서 직접 실행하지 못했다.** 로컬 `psql`이 없으며 검증 패키지는 추가하지 않았다. 반복 실행과 RLS는 감독자가 PGlite로 별도 검증해야 한다.
- SQL 검증 방법: `0001_init.sql` 후 `0002_video.sql`을 두 번 실행하여 오류 없음·뷰의 `video_id` 포함·잘못된 ID 거부를 확인한다. anon과 비운영자는 숨김·초안 조회 및 수정이 막히고, 등록 운영자는 조회·`video_id` 수정이 되는지 역할별로 확인한다.
- 실제 Supabase에 `0002_video.sql`을 사람이 직접 적용해야 한다. 이후 관리자에서 영상을 저장하고 [사이트에 반영]으로 배포한다.
- 30일 지난 수집값 갱신·삭제(R19)는 다음 작업이다. `docs/plan.md` 5단계의 관련 영상 표기 유지 여부 문구는 허용된 3단계 줄 밖이므로 수정하지 않았다.
