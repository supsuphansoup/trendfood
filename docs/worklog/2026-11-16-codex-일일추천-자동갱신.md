# 신규 음식 우선 배치와 일일 추천 자동 갱신

- 날짜: 2026-11-16
- 누가: Codex
- 관련: docs/spec.md R1·R17·R18 / docs/plan.md 자동 수집·배포

## 한 것
- 레시피 검증 뒤 사진 단계까지 통과한 새 음식은 맨 앞에 배치하고 신규로 표시한다. 사진 없는 신규 음식만 보류해 기존 추천 갱신을 막지 않는다.
- 새 음식이 없는 날도 기존 수집의 검색 신호를 재사용해 추천한다. 적합한 상승 신호가 없으면 기존 음식 순서를 순환하며 같은 날 재실행은 순서·신규 표시를 유지한다.
- 추천 갱신일·근거를 레시피 출처 확인일과 분리하고 기존 음식 순환을 신규 유행으로 표시하지 않는다. 다음 날짜에는 신규 표시를 해제한다.
- 최초 적용은 외부 수집 없이 기존 음식만 순환했다. 대표는 두바이 쫀득쿠키, 30개 음식·출처·레시피·재료 링크·사진을 보존했다.

## 바뀐 파일
- `.github/workflows/pipeline.yml` — 사진 단계 다음 추천 확정, 공개 추천 보고서 보관·요약, 기존 변경 검사·배포에 연결.
- `web/scripts/pipeline/run.ts` — 기존 스냅샷·수집 신호를 실행 중간 파일에 저장. dry-run은 공개 콘텐츠·추천 입력을 변경하지 않음.
- `web/scripts/pipeline/recommendations.ts` — 신규·검색 흐름·순환의 순서 계산과 사진 없는 신규 항목의 개별 보류.
- `web/scripts/refresh-recommendations.ts` — 추가 API 없이 최종 콘텐츠와 추천 보고서 저장.
- `web/scripts/pipeline/recommendations.test.ts` — 순환·별칭·잘못된 신호·신규·사진 보류·재실행·날짜·메타데이터·격리 CLI 테스트 9개.
- `web/src/data/content.ts`, `web/src/data/catalog-schema.ts` — 추천 메타데이터 검증·변환·병합 보존.
- `web/src/data/content/foods.json` — 첫 순환 및 추천 날짜·근거 기록.
- `web/src/components/home/home-feed.tsx`, `food-card.tsx` — 추천 날짜·근거와 실제 신규 항목 표시.
- `web/content-e2e/content.spec.ts` — 실제 대표 음식에 맞춘 검사, 추천 날짜·순환 표시와 거짓 신규 표시 없음 확인.
- `docs/automation.md` — 갱신 기준·사진 보류·보고서·운영 범위.
