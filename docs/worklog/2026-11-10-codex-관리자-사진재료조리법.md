## 한 것
- 게시 관리에 [사진·재료·조리법 고치기]를 추가하고 [글 고치기]와 동시에 열리지 않게 했다. 사진·재료·조리법은 따로 저장한다.
- 번들 사진 키 선택·미리보기·설명 편집을 추가했다. 사진 키가 바뀔 때만 히어로 사진·설명을 null로 저장한다.
- 재료 추가·이름·속성·순서·삭제를 지원한다. 기존 행의 가격·쿠팡 링크는 수정 요청에 넣지 않고, 링크가 있는 재료 삭제는 두 번 누르게 했다.
- 조리 단계 추가·삭제·순서·타이머 편집과 입력 검증을 추가했다. 저장 시 공백을 자르고 빈 타이머 키를 생략한다.
- 검증·변경분 계산·순서 변경을 순수 함수로 분리하고 단위 테스트와 가짜 Supabase E2E를 추가했다.

## 정한 것·남은 것
- 지시서가 허용한 오류 처리 방식을 적용했다. 재료 저장은 기존 행을 유지하는 개별 요청이며, 이름 맞바꾸기 고유키 충돌이나 일부 요청 실패 시 성공 알림 없이 오류를 표시하고 DB 목록을 다시 불러온다. 이미 성공한 요청은 남을 수 있으며 전체 트랜잭션은 아니다. 두 경우 모두 E2E로 확인했다.
- 사진 업로드·"AI 이미지" 표시는 이번 범위 밖이며 남아 있다. 데모 사진도 실제 서비스 전에 교체해야 한다.
- 실제 Supabase를 통한 저장은 이번 검사 범위가 아니며 가짜 Supabase에서 요청·결과를 검증했다. DB 스키마·RLS·공개 화면은 변경하지 않았다.
- 새 패키지·추가 의사결정은 없다. 커밋·push·브랜치 생성·stash·reset은 하지 않았다.

## 이어서 (2026-11-10)

### 원인·수정
- 감독자가 재실행한 상세 편집 axe 검사에서 [재료 추가]의 `color-contrast` 위반이 간헐적으로 발생했다. 기존 재료 fieldset은 첫 조회가 끝나기 전에도 버튼을 그린 채 비활성화했고, 응답 후 비활성화가 풀리면 공통 Button의 `disabled:opacity-50`과 `transition-all` 때문에 투명도가 0.5에서 1로 바뀌었다. 재료 입력 2개가 나타나는 것을 기다려도 CSS 전환은 끝나지 않을 수 있었다.
- 가짜 Supabase의 재료 GET 응답을 Promise로 보류하는 회귀 테스트를 추가했다. 수정 전에는 로딩 중 버튼 0개 조건이 실패했고, 수정 후에는 안내만 보이다가 응답을 해제하면 편집 입력·버튼이 처음부터 활성 상태로 나타난다.
- `food-details-editor.tsx`에서 첫 조회 전에는 `불러오는 중이에요…`만 표시한다. 재료 fieldset은 저장 중에만 비활성화하며, 기존 저장 중 중복 조작 방지는 유지한다.
- `admin.spec.ts`의 기존 상세 편집 axe 검사는 그대로 유지했다. 새 회귀 테스트도 로딩 후 불투명도 1과 axe를 검사한다. 고정 시간 대기나 접근성 규칙 제외는 추가하지 않았다.
- 이번 수정 파일은 `web/src/components/admin/food-details-editor.tsx`, `web/e2e/admin.spec.ts`, 이 작업 기록이다. 기존 미커밋 변경은 유지했다.
