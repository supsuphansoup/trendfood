# 네이버 검색어 트렌드 수집을 NAVER API HUB로 전환

- 날짜: 2026-11-10
- 누가: codex (AI 도구: Codex)
- 관련: docs/plan.md 1단계 수집 키 / docs/spec.md R17 / 커밋 없음(지시서에서 금지)

## 한 것
- 기본 요청 주소와 인증 헤더를 HUB 방식으로 바꾸고, 수집 실행·GitHub Actions·온보딩 안내의 Secret 이름을 `NAVER_API_HUB_KEY_ID`·`NAVER_API_HUB_KEY`로 통일했다.
- 5그룹씩 요청, 그룹당 원래 이름·공백 없는 이름 최대 2개, 14일 조회, 빠진 날짜 0 채우기를 유지했다. 키가 없을 때의 `네이버 키 없음` 로그와 예시 검색량, 오류를 `pipeline_runs`에 기록하는 흐름도 유지했다.
- Gateway 오류의 `error.message`·`error.details`, 검색어 트렌드 검증 오류의 `errMsg`, 공통 평면 오류의 `errorMessage`를 읽는다. HTTP 429 또는 본문 오류 코드 429는 `네이버 API HUB 한도 초과`로 표시하며 JSON이 아닌 오류도 HTTP 상태를 남긴다.
- `fetch`를 모두 가짜로 바꾸는 단위 테스트 13개를 추가했다. 실제 네이버 API 호출·계정 생성·이용 신청·키 발급은 하지 않았다.

## 공식 문서 확인

2026-11-10에 문서만 읽었다. 지시서의 주소·헤더와 공식 문서는 일치했고, 요청 본문과 성공 응답 필드는 기존 구현과 같았다.

- [검색어 트렌드 조회: 요청 예시·본문·응답](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend) — `POST https://naverapihub.apigw.ntruss.com/search-trend/v1/search`, `keywordGroups` 최대 5그룹, `results[].title`·`data[].period`·`ratio` 확인.
- [공통 인증·오류 형식](https://api.ncloud-docs.com/docs/naver-api-hub-overview) — HUB 헤더 2개, Gateway 객체·평면 오류 형식, 한도 초과 HTTP 429 확인.
- [이관 안내](https://guide.ncloud-docs.com/docs/apihub-migration) — 기존 개발자센터 인증 정보를 HUB에서 사용할 수 없고 새 키·주소·헤더가 필요함을 확인.
- [Application 가이드](https://guide.ncloud-docs.com/docs/apihub-application) — Subscription의 서비스 이용 신청, Application 등록·검색어 트렌드 선택, 인증 정보의 Application Key·Client ID·Client Secret, 검색어 트렌드 월 50,000건 확인.

## 정한 것·남은 것

- 지시서 밖의 제품·수치 결정 없음. 그룹당 검색어 5/20개 충돌은 지시대로 현재 최대 2개를 유지했다. 한도 주석은 월 50,000회와 추출 요청 최대 20개 기준 하루 4회로 적었으며, 20개는 기존 LLM 요청의 상한 문구이고 결과를 강제로 자르는 제한은 아니다.
- 공식 공통 오류 문서는 429 설명에 하루 허용량을 적고 Application 가이드는 월 한도를 안내한다. 어느 한쪽으로 일 한도를 확정하지 않았고 기존 조사 보고서의 확인 필요 항목을 유지했다.
- `web/.env.example`은 존재하지 않아 새로 만들지 않았다. `AGENTS.md`에는 옛 환경변수 이름이 없어 수정하지 않았다.
- 실제 키 발급·GitHub Secret 등록·실제 연동 확인은 사람의 다음 작업이다. 이번 작업은 가짜 응답과 키 없는 실행까지 검증했다.
- 커밋·push·브랜치 생성·stash·reset은 하지 않았다.
