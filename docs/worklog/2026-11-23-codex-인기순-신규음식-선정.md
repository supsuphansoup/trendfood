# 신규·대기 후보의 인기순 사진 처리와 공개

- 날짜: 2026-11-23
- 누가: Codex
- 관련: `docs/spec.md` R17 / `docs/plan.md` 5단계 / `docs/automation.md`

## 한 것

- 최근 검증일만으로 세 개를 골라 높은 인기 점수의 대기 후보가 밀리던 문제를 재현했다. 신규·대기 원고를 이번 실행의 점수순으로 함께 비교하고, 사진 처리와 최종 공개에도 같은 순서를 적용했다.
- 사진을 확보한 상위 세 개를 점수순으로 공개한다. 사진이 먼저 준비된 하위 후보 때문에 상위 후보의 사진 생성이 생략되던 조건도 고쳤다. 상위 후보의 사진이 끝내 통과하지 못하면 다음 후보를 검토한다.
- 검색 신호가 없는 대기 원고는 이미 수행하던 공식 원문 재확인 결과에서 중복 없는 최근 영상 수를 계산한다. 검색 배수는 1로 두며 상승을 추정하지 않는다. 정규 수집·사진 전용·대기 공개 실행에 연결했다.
- 3개는 일일 상한이며 후보가 없으면 추가하지 않는다. 검증·사진 검색·AI 생성의 기존 호출 한도는 늘리지 않았다.

## 바뀐 파일

- `web/scripts/pipeline/publish-policy.ts` — 공통 인기순 정렬, 음식명 정규화, 잘못된 점수 제외, 동점 순서 고정.
- `web/scripts/pipeline/recommendations.ts` — 사진을 확보한 상위 세 개 선정과 공개 순서, 대기 전용 점수 전달.
- `web/scripts/auto-photos.ts`, `web/scripts/photo-automation.ts` — 공통 인기순을 사진 처리에 연결하고 상위 후보 기준으로 남은 자리를 판단.
- `web/scripts/pipeline/discovery.ts` — 원문 재확인에서 대기 후보의 현재 영상 언급 신호 계산.
- `web/scripts/pipeline/run.ts`, `web/scripts/restore-pending-photos.ts` — 현재 검색 신호가 없는 대기 후보의 신호를 추천 입력에 전달.
- `web/scripts/pipeline/recommendations.test.ts`, `web/scripts/pipeline/discovery.test.ts`, `web/scripts/photo-automation.test.ts` — 인기순 공개·사진 생성·대기 전용·동점·비정상 점수 회귀 검사.
- `AGENTS.md`, `docs/automation.md` — 인기순 기준과 하루 최대 3개 정책 설명.

## 정한 것·남은 것

- 인기 기준은 기존의 검색 상승 배수 × (1 + log2(영상 언급 수))를 유지했다. 동점이면 최근 검증일 다음 음식 주소순으로 고정했다. 실시간 전체 시장의 절대 순위로 설명하지 않는다.
- 테스트의 외부 API·이미지 생성은 가짜 응답을 사용했다. 이번 보완 검증에서 유료 OpenAI 호출은 하지 않았다.
- 변경된 순서로 실제 정기 실행에서 후보가 선정·사진 처리·배포되는지는 다음 실행 결과에서 확인해야 한다.
