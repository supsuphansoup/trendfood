# 수집·사진 자동화를 하루 한 번으로 변경

- 날짜: 2026-11-12
- 누가: Codex
- 관련: 팀장의 "하루 한번으로 할건데 가장 적합한 시간 찾아봐" 요청

## 한 것
- 한국 이용자를 대상으로 음식·사진 수집부터 검사·배포까지 매일 10:17 KST에 한 번 실행하도록 변경했다. UTC 예약은 `17 1 * * *`이다.
- 현재 네이버 조회 종료일은 UTC 전날이므로 한국 시간 09:00 이전에는 한국 달력의 그저께를 요청한다. 09:00 이후로 잡고 점심 전 검사·배포 여유를 두었다. 정각 혼잡을 피하라는 GitHub 공식 안내에 따라 17분을 선택했다.
- 사진 검색도 UTC 날짜별 5개 순환으로 변경했다. 기존 8시간 순환으로 하루 한 번 실행하면 준비 중 15개에서 같은 5개만 반복하는 문제를 회귀 검사했다.

## 바뀐 파일
- `.github/workflows/pipeline.yml` — 하루 한 번 10:17 KST 예약.
- `web/scripts/photo-automation.ts`, `photo-automation.test.ts` — 일별 사진 순환과 15개·20개 전체 순회 및 같은 날 재실행 검사.
- `web/scripts/pipeline/sources.test.ts` — 실제 워크플로의 단일 예약·한국 시간 변환·그 시각 네이버 요청의 전날 종료일 검사.
- `AGENTS.md`, `docs/automation.md` — 운영 시각과 선택 근거·제약 동기화.

## 정한 것·남은 것
- 한국 대상·하루 한 번 전체 자동화를 전제로 선택했다. 방문자 시간대 통계로 입증된 최적 시각은 아니다.
- 네이버 공식 API 문서에서 정확한 일별 데이터 갱신 시각을 확인하지 못했으므로 10:17에 전날 자료가 완전히 제공된다고 보장하지 않는다. GitHub 예약도 지연될 수 있다. 정확한 배포 완료 시각을 보장하지 않는다.
- 실행 횟수는 하루 3회에서 1회로 줄이고 기존 실행당 음식·사진 확인 한도는 유지한다. 수동 실행은 계속 가능하다.
- 근거: [GitHub schedule 공식 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [네이버 HUB 검색어 트렌드 공식 문서](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend), 저장소 `web/scripts/pipeline/sources.ts`의 UTC 종료일 계산. 네이버 데이터 공개 시간이나 사이트 이용 피크를 추정 사실로 기록하지 않았다.
