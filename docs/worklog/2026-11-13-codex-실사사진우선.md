# 생성 예시를 검증된 실사로 점진 교체

- 날짜: 2026-11-13
- 누가: Codex
- 관련: docs/spec.md R1·R4·R14 / docs/automation.md 사진

## 한 것
- 사용자가 승인한 실사 우선 방식에 맞춰, 준비 중 사진뿐 아니라 등록부의 음식 주소와 일치하는 생성 예시도 실사 검색 대상으로 포함했다.
- 기존 하루 기본 5개·음식별 후보 최대 6장·10:17 KST 예약을 유지한다. 본문이나 히어로에 기존 실사·업로드 사진이 있으면 자동 교체하지 않는다.
- 실사가 기존 라이선스·메뉴·레시피·구도 검사를 모두 통과할 때만 연결한다. 생성 히어로는 해제하고 생성 원본 파일과 프롬프트 등록부는 보존한다.
- 검색·다운로드·판별 실패에는 기존 생성 이미지와 안내를 그대로 유지한다. 실행 보고서와 콘솔에 실제 생성→실사 교체 및 생성 유지 여부를 기록한다.

## 바뀐 파일
- `web/scripts/photo-automation.ts` — 생성 예시 검색, 검증 후 교체, 실패 시 보존 및 보고.
- `web/scripts/auto-photos.ts` — 실사 교체·생성 유지 개수 출력.
- `web/scripts/photo-automation.test.ts` — 검색 대상·날짜 순환, 성공 교체, 실패 보존 회귀 테스트 3개 추가.
- `docs/automation.md`·`AGENTS.md` — 승인된 실사 우선 운영 규칙 반영.
- `docs/worklog/2026-11-13-codex-실사사진우선.md` — 이번 작업 기록.

## 정한 것·남은 것
- 실사 확보가 실패해도 기존 이미지를 없애지 않는 방식과 기존 일일 처리량 유지는 사용자 승인 범위 안에서 적용했다. 검증 기준을 낮추지 않았다.
- 이 작업 환경의 외부 다운로드가 `fetch failed` / `EACCES`로 차단돼 새 실사를 내려받거나 실제 검색→다운로드→AI 판별을 끝까지 실행하지 못했다. 실제 사진 교체는 0개이며 실사 4개·생성 예시 26개가 유지된다. 새 테스트는 외부 호출을 가짜 응답으로 대체한 로직 검증이다.
- `.git` 쓰기가 허용되지 않아 커밋·push·운영 배포는 하지 않았다. 변경을 예약 실행 환경에 반영하고 실제 사진 실행 보고서를 확인하는 작업이 남았다.
- 공개 콘텐츠 빌드 결과를 복원했고 기존 `http://localhost:3000` 미리보기 서버는 유지한다.
