# 음식 이미지와 실사 우선 자동화의 실서비스 배포

- 날짜: 2026-11-13
- 누가: Codex
- 관련: docs/spec.md R1·R4·R14·R18 / docs/automation.md

## 한 것
- 사용자가 전체 액세스로 변경한 후 GitHub API와 원격 main 연결·쓰기 권한을 실제 확인했다. 운영 변수는 공개 JSON·자동 반영·사진 검색이 이미 활성화돼 있어 변경하지 않았다.
- 이전 작업에서 준비한 생성 이미지 26개, 검토를 유지한 실사 4개, 생성 표시와 출처 표시, 실사 우선 자동 검색을 함께 반영한다. 제외된 사진과 생성 원본 기록은 보존한다.
- 원격 main에 추가된 재료 상품 링크 3개를 보존하며 최신 main에 통합한다. `photos_only` 실행 설명도 생성 이미지의 실사 검색을 포함하도록 정리한다.

## 바뀐 파일
- 이전 사진 검색 확장·사진 품질 검토·음식 생성 이미지·실사 우선 작업에서 준비한 코드·사진·등록부·문서와 각 작업 기록.
- `.github/workflows/pipeline.yml` — 선택 검색처 환경변수 및 사진 전용 실행 설명.
- `docs/live-publish.md` — 전체 액세스 전환 이후 상태와 실제 배포 기록 경로.
- `docs/worklog/2026-11-13-codex-실서비스배포.md` — 이번 배포 검사와 결과.
- 개인 설정·비밀값·전달 ZIP·로컬 빌드 결과는 커밋하지 않는다.

## 운영 배포와 실제 서비스 확인
- `git pull --rebase origin main`으로 재료 링크 3개가 추가된 `7e771a6`을 통합했다. 통합 전 검사한 커밋과 통합 후 트리의 `git diff --exit-code`가 0임을 확인했다.
- 운영 main에 `7285621`을 반영했다. [deploy 실행](https://github.com/supsuphansoup/trendfood/actions/runs/43435480844)은 Cloudflare 실제 업로드까지 성공했다. 배포 주소: `https://55c78787.trendfood.pages.dev`.
- [운영 CI](https://github.com/supsuphansoup/trendfood/actions/runs/43435480768)도 성공했다. 실제 출력은 unit `tests 129`·`pass 129`, e2e `122 passed (1.6m)`, 공개 콘텐츠 `8 passed (39.4s)`다.
- `node data/live-smoke.mjs`: 실제 `https://trendfood.pages.dev`에서 모바일 390px·PC 1280px 각각 카드 29개와 사진 30개 로딩, 두바이 쫀득쿠키·말차 라떼 상세 200 및 재료 영역, 가로 넘침 없음, 사이트 자원 400 이상 응답 0개를 확인했다. 생성 카드 안내는 현재 26개이고 준비 중 표시는 없다.
- 추가 실서비스 검사 첫 실행은 상세 히어로가 `main` 바깥에 있는데 `main img`로 찾은 검사 코드 때문에 실패했다. 임시 검사 선택자와 실제 생성 안내 문구를 바로잡은 뒤 모바일·PC 모두 통과했다. 제품 코드를 바꾸거나 실제 이미지 오류를 숨기지 않았다.
- `web/data/live-production-dubai-chewy-cookie-mobile.png`·`live-production-dubai-chewy-cookie-desktop.png`를 열어 운영 사진과 생성 안내를 확인했다. 관련 임시 검사·스크린샷은 기존 무시 경로에 둔다.
- 예약 워크플로 `pipeline`의 상태가 `active`임을 확인했고 매일 10:17 KST 설정을 유지한다. [사진 전용 실행](https://github.com/supsuphansoup/trendfood/actions/runs/43435744419)을 `photos_only=true`·`photo_limit=5`로 요청했다.
- 사진 전용 실행이 성공했다. `photo-report.json`의 결과는 적용 0개·보류 5개이며 모두 `retainedGenerated=true`다. 크로플·새우 로제 떡볶이·들기름 막국수·민트초코 라떼·달고나 뽑기를 확인했다. 실제 사진 다운로드와 AI 판별이 수행됐고 치킨 크로플, 따뜻한 민트 음료·푸딩, 달고나 커피처럼 요청 레시피와 다른 사진을 거절했다. 나머지 항목은 허용 조건에 맞는 후보가 없었다. 적합하지 않은 실사로 바꾸지 않고 기존 생성을 유지하는 경로가 운영에서도 확인됐다.
- 사진 변경이 없으므로 해당 실행의 추가 `publish`는 정상적으로 건너뛰었다. 앞선 Cloudflare 배포는 그대로 유지되며 현재 실사 4개·생성 예시 26개·준비 중 0개다.
- 운영 보고서에 Openverse 검색 경고가 있었다. 같은 공식 검색 요청을 별도 확인한 결과 HTTP 504와 `origin_gateway_timeout` 응답이었다. 외부 검색처의 장애이며 Commons 검색과 판별은 정상 수행됐다. Pexels 키 미설정 상태는 보고서의 `pexels=false`와 일치한다.

## 정한 것·남은 것
- 호스팅·AI 모델·일일 검색량·예약 시각은 유지한다. Pexels 키는 현재 없으므로 Commons·Openverse를 사용한다.
- 실제 서비스 배포·CI·사진 전용 실행·모바일/PC 이미지 로딩 확인을 마쳤다. 적합한 실사를 새로 확보한 것은 아니므로 실사 수가 늘었다고 보고하지 않는다.
- Openverse 외부 서버의 복구와 선택 사항인 Pexels 키 등록은 남아 있다. 자동 검색은 Commons를 계속 사용하고, 검증을 통과한 실사를 찾으면 다음 예약 실행에서 교체한다.
