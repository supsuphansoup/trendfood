# 먹방 중심 수집과 조리법 없는 유행 음식 소개

- 날짜: 2026-11-16
- 누가: codex (AI 도구: Codex)
- 관련: docs/automation.md 실행과 반영 조건 / docs/plan.md 수집 확장 / 사용자 요청: 먹방에서 유행 음식을 찾고, 만들 수 있는 음식에만 레시피·재료 구매 제공

## 한 것
- 기본 검색어 5개 중 3개를 먹방·신상 시식으로 변경했다. 최근 7일 인기 검색과 48시간 최신 검색, 기본 검색 10회와 음식 추출 최대 20개는 유지했다. ‘집에서 만들 수 있는 음식 위주’ 추출 제한을 제거했다.
- 검색 관심 증가·서로 다른 제작자 검증을 통과하면, 조리법이 없어도 같은 AI 응답의 음식 소개 인용을 원문과 대조해 `discovery`로 등록할 수 있다. 레시피의 사용량·시간·분량·단계 검증은 유지했다. 음식명 없는 인용·허위 출처·없는 문구는 거절한다.
- 음식 소개에는 재료·조리 단계·구매 주소를 만들지 않는다. 카드·상세에서 조리 시간·난이도·만드는 법·재료 담기를 숨기고 음식 정보·출처·찜을 제공한다. 홈 대표는 ‘오늘의 음식’으로 표시한다.
- 기존 소개도 이후 완전한 조리법을 확인하면 같은 주소·사진·유행 시기를 보존해 레시피로 보강한다. 새 음식 우선, 기존 최대 3개 처리 안에서 동작한다. 레시피가 여전히 없으면 기존 소개를 보존한다.
- 음식 소개 사진은 조리법 없이 이름·소개 원문으로 대조하며 기존 이미지·메뉴·이용 조건 검사는 유지한다. 새 소개도 사진을 확보해야 공개 추천에 들어간다.

## 정한 것·남은 것
- 검색어의 먹방 3 : 레시피 2 배분과 소개 인용 상한 120자·25단어는 이번 구현에서 선택했다. 기존 검색·AI 호출 횟수 한도와 예약 시각은 늘리지 않았다. 프롬프트 변경에 따른 예약 실행의 실제 토큰량은 실행 보고서에서 확인해야 한다.
- `discovery`의 조리 시간 0과 기존 난이도·인분 필드는 저장 형식 호환용이며 화면에 표시하지 않는다. 소개에는 재료·단계를 비워야 하고 기존 레시피는 빈 값을 허용하지 않는다.
- 공개 음식 JSON·사진 파일은 변경하지 않았다. 이번 작업으로 추가된 실제 음식은 0개이며, 새 기준의 실제 수집·소개 등록·사진 확보·공개 반영 결과는 다음 예약 실행에서 확인해야 한다. 사진이 없거나 유행 근거·원문 검증이 실패하면 계속 보류한다.
- 기존 품절 상품 확인·브라우저 연결 보류 작업은 진행하지 않았다. 파트너스 승인 전 상품 상세 자동 연결의 재고 확인 보류도 유지한다.
