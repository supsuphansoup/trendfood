## 한 것
- 빌드 전 게시된 음식의 사진 UUID만 모아 Supabase Storage `food-photos`에서 WebP를 내려받도록 구현했다. 파일 경로·응답 코드·콘텐츠 형식·2MB 제한을 검증하고 실패하면 빌드를 멈춘다. 원본 출처 주소에서는 내려받지 않는다.
- 공개 화면은 내려받은 `/photos/…` 경로를 사용하고, 실제 상세 히어로의 출처·라이선스를 표시한다. blur 데이터가 없는 사진은 빈 placeholder를 사용한다.
- `TF_SEED_ONLY=1`에서만 참치 김밥에 테스트 사진과 출처를 연결한다. 직접 만든 32×24 단색 WebP를 추가했다. 키 없는 일반 로컬 빌드의 예시 데이터는 유지한다.
- 관리자 안내와 지정된 문서 문장을 갱신했다. **필수 검사가 샌드박스 경로 권한 오류로 실패해 완료 조건은 충족하지 못했다.**

## 정한 것·남은 것
- 범위 확대·새 패키지·커밋·push·브랜치 생성·stash·reset·기존 파일 삭제 없음. package-lock.json·CLAUDE.md·DB·워크플로·수집 코드는 변경하지 않았다.
- 새 fixture는 설치된 Python Pillow로 생성했다. Node의 sharp 실행은 프로젝트 상위 경로 권한 오류로 시작하지 못했다.
- 도구 확인용 `npx skills find 'nextjs playwright'`는 npm registry 접근 EACCES로 실패했다. 설치한 스킬·패키지는 없다.
- 필수 검사 4개·Playwright 5회 반복·테스트 빌드 산출물·스크린샷 검증 모두 감독자가 다시 실행해야 한다. 쿠팡 팝업 테스트까지 도달하지 못했으므로 해당 예외에 해당하지 않는다.
- 사진 삭제와 메인 카드 출처 표시 여부는 후속 작업·팀 결정으로 남긴다.
- 감독자 검사 후 수정: food-details-editor.tsx 89행의 안내 문구를 JSX 문자열 표현식으로 감싸 표시 글자를 유지했고, mvp.spec.ts 39·51·62행의 콜백 매개변수에 HTMLImageElement[] 타입을 명시했다.
