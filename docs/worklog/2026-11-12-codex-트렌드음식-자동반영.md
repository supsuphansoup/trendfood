# 출처 확인 콘텐츠와 새 트렌드 음식 자동 반영

- 날짜: 2026-11-12
- 누가: Codex
- 관련: 팀장의 기존 음식 실정보 보강·2020년 이후 유행 음식 추가·새 음식 자동 진행 요청, `docs/automation.md`

## 한 것
- 기존 10개 주소를 유지하면서 실제 출처가 있는 음식 30개(레시피 27개·완제품 안내 3개), 유행 연도·출처·사용량을 채웠다. 검토한 CC0/퍼블릭 도메인 참고 사진 10개를 등록하고 나머지 20개는 사진 준비 중으로 표시했다.
- 하루 3회 기존 수집 뒤 검색 상승·복수 제작자·실제 설명란의 레시피 근거를 확인해 새 음식만 추가한다. 전체 검사 통과 후 자동 커밋하고 재사용 배포 워크플로를 직접 호출한다.
- 최신 main의 관리자·사진 업로드·영상·통합 장바구니 기능을 유지했다. 공개 모드는 JSON이며 기존 DB 관리자 편집과의 차이를 운영 문서에 명시했다.

## 바뀐 파일
- `web/src/data/content*`, `web/src/assets/curated/`, 사진 크레딧·동기화·콘텐츠 스크립트 — 실제 출처 콘텐츠와 재현 가능한 가져오기.
- `web/scripts/pipeline/autopublish*`, `run.ts`, `sources.ts` — 설명란 조회, 근거 대조, 중복·실패·재실행 처리와 보고서.
- 공개 홈·상세·공통 이미지·장바구니 — 실제 출처·연도·사진 준비 중 표시, 가짜 수치 제거.
- `.github/workflows/` — 예약 수집에서 검사·저장·배포까지 연결, CI에 공개 콘텐츠 검사 추가.
- `docs/automation.md`, 안내 문서·`AGENTS.md` — 팀장이 요청한 자동 반영 범위와 운영 방법. 기존 `web/README.md` 내용은 통합 운영 문서로 옮겼다.

## 정한 것·남은 것
- 팀장의 자동 진행 요청을 새 글의 개별 승인 생략으로 해석했다. 1.3배 이상·최근 복수 제작자·한 원문의 완전한 레시피·전체 검사 통과 조건, 실행당 최대 3개·누적 1000개로 제한했다.
- 연도는 자동 수집에서 확인한 시기이며 최초 유행 연도를 주장하지 않는다. AI 자동 대조·개별 미검수·직접 조리 미검증을 글에 표시한다.
- 기존 공급자·모델 선택을 유지한다. GitHub 변수 `PIPELINE_AUTO_PUBLISH=true`, `TF_CONTENT_ONLY=1`을 설정했다.
- 사진 확보·선별은 완전 자동화하지 않았다. 새 음식은 사진 준비 중으로 시작하며 플랫폼 썸네일과 AI 생성 사진을 쓰지 않는다.
- 기존 로컬 작업은 최신 main 반영 과정에서 Git의 autostash에 보존되어 있다.
