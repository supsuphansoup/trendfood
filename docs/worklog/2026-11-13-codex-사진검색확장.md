# 사진 검색처 확대와 사진 없는 음식의 텍스트 표시

- 날짜: 2026-11-13
- 누가: codex (AI 도구: Codex)
- 관련: 팀장 승인 — Openverse·Pexels 추가 + 사진 없는 음식의 텍스트 카드 / R1·R4·R14

## 한 것

- Commons 외에 Openverse(Flickr 사진)·Pexels 공식 API를 연결했다. 원문·파일 ID·허용 주소·작가·이용 조건·해상도를 검사하고 기존 음식/레시피/구도 판별을 적용한다. 검색처 장애는 다른 출처를 막지 않는다. Pexels 키는 해당 검색 API에만 전송한다.
- Openverse는 기존 CC0·퍼블릭 도메인·CC BY 4.0·CC BY-SA 4.0 조건을 유지한다. Pexels는 별도 Pexels License를 표시하고 푸터·상세에 서비스/작가/원문/라이선스 링크를 제공한다.
- 사진 없는 음식은 내부 `pending`을 유지해 재검색하면서 공개 목록의 이미지 공간·준비 중 문구를 없앴다. 메인·상세도 사진이 없으면 소개 높이를 줄였다. 찜·레시피 이동·재료 담기·출처를 유지했다. 사진 확보 전 게시를 막지는 않는다.
- 앞선 검토에서 제외한 자동 사진의 키가 교체 사진까지 막던 문제를 고쳤다. 제외 기록·파일·출처는 보존하고 교체 사진은 새 키로 저장한다.

## 정한 것·남은 것

- 검색 출처 확대와 텍스트 표시를 적용한다는 직전 제안에 대한 사용자 승인을 범위로 삼았다. 새 패키지는 설치하지 않았다. `find-skills`의 `npx.cmd --yes skills find 'photo api'`는 네트워크 제한으로 `EACCES`가 발생해 공식 API·설치된 Next.js 문서를 기준으로 구현했다.
- Openverse는 임의 호스트 다운로드를 허용하지 않도록 현재 Flickr 사진만 지원한다. 다른 공급자는 이번 범위에서 추가하지 않았다. 음식별 이미지 판별 후보 한도는 3장에서 6장으로 늘려 새 출처를 대조하며 실제 AI 비용이 늘 수 있다.
- 실제 외부 API·사진 다운로드·AI 판별은 이 환경의 외부 네트워크 제한과 키 미연결 때문에 미검증이다. API 응답을 모의 처리한 검증과 실제 로컬 정적 화면 검증을 구분한다. 새 사진을 확보했다고 보고하지 않는다.
- GitHub Actions의 `PEXELS_API_KEY` 등록 여부는 확인/변경하지 않았다. 키를 Secret에 추가해야 Pexels가 동작한다. 현재 `.git` 쓰기 제한으로 커밋·push·배포는 하지 않았다. 공개 사이트는 이전 버전이며 기존 미추적 `.claude/`는 보존했다.
