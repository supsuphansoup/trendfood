# 자동 사진 검사를 실제 목록과 상세 화면에 맞춤

- 날짜: 2026-11-26
- 작업자: Codex
- 관련 문서: `docs/automation.md`

## 한 것

- 11월 23~26일 최근 수집 실행 네 건에서 신규 게시가 모두 0건이었다. 26일 오전 실행(45721137682)은 라면·베이글·피자 원문을 검증했지만 추천 보고서의 11개 원고 모두 게시용 사진을 확보하지 못했다. 이미지 생성 요청 6회도 모두 사진 검사에서 보류됐다.
- 짜장면과 핫도그 등의 구도 검사에 이전 상세 비율이 사용된 것을 확인했다. 실서비스에서 1280px 화면의 목록 카드 568×240, 상세 540×540과 390px 화면의 상세 350×262.5를 측정했다.
- 실사와 생성 예시 검사에 현재 PC 2열 카드·PC 정사각 상세·모바일 4:3 상세를 공통으로 사용한다. 생성 프롬프트에도 같은 구도를 반영한다.

## 바뀐 파일

- `web/scripts/photo-assets.ts`에 검사 미리보기 생성 로직을 추가했다.
- `web/scripts/photo-automation.ts`와 `web/scripts/generated-photo-automation.ts`에서 공통 미리보기를 사용한다.
- `web/scripts/photo-automation.test.ts`와 `web/scripts/generated-photo-automation.test.ts`에서 두 검사 요청에 담긴 미리보기 크기와 구도를 확인한다.
- `docs/automation.md`에 검사 화면 비율을 기록했다.

## 결정과 남은 확인

- 모바일 미리보기는 실제 4:3 비율을 352×264 정수 픽셀로 재현했다. PC 카드는 데스크톱 2열에서 가로가 가장 넓어지는 배치를 사용했다.
- 원격 기준은 `1d8ac79c2d7fd1a83d33dd22a7f8289e473a7a08`이다. 일상 레시피에서도 상단 유행순위를 유지한 팀원 커밋을 작업 전에 fast-forward로 통합했다. 파일이 겹치지 않아 충돌은 없었다.
- 26일 오전 실행에서 한국 날짜 기준 이미지 생성 요청 한도 6회를 사용했다. 변경한 비율로 사진이 통과해 게시되는 결과는 이후 정기 실행에서 확인할 수 있다.
