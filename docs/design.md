# vviralfood 디자인 기준 (docs/design.md)

> 버전 1.0 · 2026-11-04 · 포토 피드형 확정안 기준
> 실제 화면(`web/`) + 이 문서가 시각 기준. 토큰 파일: `web/src/app/theme.css` (앱이 직접 불러오는 유일한 원본)

2026-11-16: 유행 음식 탐색이 기본이고 만들기는 선택이다. 홈 대표를 ‘오늘의 음식’으로 표시한다. 원문 소개만 있는 음식은 ‘음식 알아보기’·‘소개 출처 보기’를 제공하고, 조리 시간·난이도·만드는 법·재료 담기는 표시하지 않는다. 확인된 레시피가 있을 때만 기존 조리법·재료 구매 화면을 제공한다. 사진과 토큰·레이아웃은 기존 기준을 따른다.

## 0. 원칙
2026-11-26 홈 음식 목록 사진(R2): 2열·3열 카드의 사진은 기존 영역 안에서 원본 비율로 중앙에 맞춘다. 남는 영역은 카드의 보조 배경색으로 두고, 마우스를 올리거나 눌러도 사진을 확대하지 않는다. 사진 영역은 음식 상세로 연결한다.

2026-11-26 홈 전체 화면 B안(R1): 헤더 아래 첫 화면을 추천 음식 사진 한 장으로 채운다. 사진 위에 서비스 안내, 음식명, 유행 배경과 상세 행동을 표시한다. 아래 추천 카드 대신 스와이프·드래그·좌우 버튼으로 전체 장면을 넘긴다. 자동 넘김은 8초이며 일시정지·재개 버튼을 제공한다. 탭이 숨겨지거나 마우스를 올리면 기다리고, 키보드 탐색이나 직접 전환 후에는 재개 버튼으로 시작한다. 동작 줄이기 설정에서는 자동 넘김이 기본으로 꺼지고 수동 전환은 즉시 동작한다. 대표 음식 사진을 자르는 범위는 홈에만 적용한다.

2026-11-26 브랜드 변경: 서비스 이름은 `vviralfood`로 표기한다. 홈·상세·안내 페이지의 헤더와 브라우저 탭은 새로 받은 검은색 로고 PNG를 사용한다. 페이지 제목과 로고의 대체 텍스트는 서비스 이름을 쓴다.

2026-11-24 홈 포스터와 음식 목록(R1): 중앙 음식 사진은 여백 안에 원본 비율로 표시하고 양옆에 이웃 추천 음식을 보여준다. 이전·다음 화살표, 이웃 카드, 사진의 가로 드래그·스와이프로 추천 음식을 순환한다. 목록은 모바일과 PC에서 기본 2열로 표시하고 3열로 바꿀 수 있다. 중앙 사진 아래에 음식명·유행 배경·상세·영상 버튼을 두고 현재 위치를 표시한다. 기존 테마와 사진의 상세 링크·출처 안내·동작 줄이기를 유지한다. 아래의 가로 순위 탭과 설명·사진 분할 배치보다 이 기준이 우선한다.

2026-11-24 홈 대표와 추천 순위(R1). 흰 바탕에 ‘유행 음식과 집밥’과 ‘음식 목록’ 바로가기를 둔다. 대표 음식의 설명과 사진 아래에 1·2·3위 버튼을 한 줄로 표시하고 선택한 칸에 밑줄을 둔다. PC는 설명과 사진을 나란히 두고, 모바일은 설명과 상세·영상 버튼 다음에 사진을 보여준다. 순위를 고르면 밑줄과 대표 내용이 짧게 전환되며, 기기의 동작 줄이기 설정을 따른다. 확인된 유행 기록을 바탕으로 추천한다는 안내는 순위 아래에서 펼쳐 볼 수 있다.

2026-11-23 홈 첫 화면(R1): ‘유행 음식부터 집밥 레시피까지’를 홈의 주 제목으로 쓰고, 유행 배경과 집에서 만드는 데 필요한 재료·조리법을 설명한다. 토마토 레드 소개 면에 흰 제목·설명과 흰 바탕의 ‘음식 둘러보기’ 버튼을 둔다. 제목은 PC 1280px에서 72px, 모바일에서 36px다. PC는 소개 왼쪽·오늘의 음식 오른쪽, 모바일은 소개 다음 오늘의 음식 순서다. 오늘의 음식은 사진 아래에 음식명·상세 링크·유행 배경을 배치하고, 사진의 원본 비율과 클릭 영역을 보존한다. 아래의 이전 홈 대표 배치·글자 크기보다 이 기준이 우선한다.

2026-11-19 대표 사진 구도 보존(R1): 메인 대표는 실사·생성 예시 모두 원본 비율로 표시하며 음식 가장자리를 자르지 않는다. 화면을 지나치게 차지하지 않도록 이미지 높이는 모바일 280px·PC 400px까지로 제한하고, 제한에 걸려 생기는 여백은 기존 보조 배경색으로 둔다. 사진은 중앙 정렬하며 확대한 흐린 복제 배경은 사용하지 않는다. 아래 과거의 메인 대표 고정 비율·오른쪽 정렬 설명보다 이 기준이 우선한다.

2026-11-19 사진 탐색 수정(R1·R4): 메인 대표 사진 전체와 모든 목록 카드 사진은 해당 음식 상세로 이동하는 링크다. 이미지 중앙과 여백을 포함한 사진 영역 어디서든 클릭할 수 있고, 키보드로도 진입할 수 있어야 한다. 카드의 찜 버튼은 독립 동작을 유지한다.

2026-11-18 사진 표시 변경: 메인 대표 사진·카드와 상세 사진 위의 유형 배지·제목 아래 유형 안내는 표시하지 않는다. 상세 하단 출처 영역에 기본 접힌 `사진 정보`를 두고 열었을 때 AI 생성 예시·참고 사진 안내와 출처·라이선스·생성 기록을 제공한다. 기존 작은 보조 글자색을 사용하되 요약의 터치 영역은 44px 이상이며 키보드로 열고 닫을 수 있어야 한다. 대체 설명은 유지한다. 아래 과거의 표시 설명보다 이 기준이 우선한다.

2026-11-25 일상 레시피 진입(R1·R2): 기존 카테고리 줄에서 ‘전체’ 다음에 ‘일상 레시피’를 둔다. 기존 탭의 글자·44px 이상 터치 영역·선택 밑줄과 강조색을 사용하고 모바일은 같은 줄에서 가로로 탐색한다. 기본 대표·목록은 최신 유행 연도와 같은 연도의 추천 순서에 따라 유행 음식만 보여준다. 일상 레시피에서는 대표·유행 음식 모음·연도 필터를 숨기고 순위 없는 레시피 목록을 보여준다.

2026-11-18 상세 순서 변경(R4·R6): 사진·제목 다음에 재료 장바구니와 만드는 법을 먼저 배치한다. PC는 좌 장바구니 5 : 우 조리법 7, 모바일은 장바구니 → 만드는 법 순서다. 음식 소개(어떤 음식인가요)·참고한 출처·사진 출처·원본 영상은 조리 구역 아래에 둔다. ‘편의점·마트에서 사서 맛보기’ 구역은 표시하지 않는다. 소개 전용 음식에는 조리법·장바구니를 만들지 않는다.

2026-11-18 음식 발견 중심 개편(R1·R2): 사용자가 UI 검토에서 제안한 탐색 중심 개선을 승인했다. 아래 이전 대표 크기·안내·카드 행동 기준보다 이 항목을 우선한다.

- 색은 흰 바탕 `#FFFFFF`, 먹색 `#252525`, 제목·대표 행동 레드 `#C93135`, 본문 `#383C40`, 안내 `#60656B`, 목록 바탕 `#F5F6F7`을 유지한다. 로고 원본은 보존한다. 강조색을 늘리지 않고 대표 음식의 사진·제목에 시선을 모은다.
- Pretendard를 유지하고 대표 음식명은 PC 64px·태블릿 48px·모바일 36px, 음식 설명은 18px다. 목록 설명은 2줄 미리보기이며 전문은 상세에서 제공한다.
- 배치: `대표 [유행 배경·음식명·상세 링크 | 음식 사진] → 접을 수 있는 AI·출처 정보 → 카테고리 → 음식 모음·목록`. PC 좌우 분할과 2열 목록·세 번째 넓은 음식은 유지한다. 모바일은 사진부터 보여주되 대표 사진을 2:1로 낮추고 반복 안내를 접어 탐색 진입을 앞당긴다. 실사 원본 구도·생성 예시 표시를 유지한다.
- 대표와 카드의 설명은 확인된 `history.note`를 우선한다. 기록이 없으면 기존 음식 설명을 쓴다. 대표는 첫 문장을 온전히 보여주고 카드는 2줄로 미리 본다. 추천 이유가 기존 음식 순환이면 ‘다시 보는 유행’, 새 원고면 ‘새로 소개하는 음식’으로 표시한다. 새 원고라는 이유만으로 최신 유행을 주장하지 않는다.
- 목록에는 ‘유행 음식 / 최근 발견 / 유행 기록’ 모음을 둔다. 출처가 있는 유행 연도 또는 음식 소개는 유행 기록, 유행 기록이 없는 레시피는 일상 레시피로 묶는다. 완제품을 레시피로 분류하지 않는다. `collection` 주소로 선택을 보존하고 검색·찜·기존 필터와 함께 적용한다.
- 홈의 주 행동은 ‘음식 살펴보기’다. 조리 시간·재료 구매 버튼을 홈에서 빼고 상세의 만드는 법·재료 구매로 이어지게 한다. 실시간 인기 순위와 기록된 유행 시기의 차이는 목록 위에 밝힌다.
- 초안 검토: 식욕을 돋우는 새 사진이 필요하다는 문제와 화면 구성 문제를 구분한다. 이번에는 사진 파일·수집 데이터·자동화·추가 API 호출을 바꾸지 않는다. 같은 버튼이 반복되는 길이를 줄이고 음식 배경을 먼저 읽게 하는 변경에 집중한다.

2026-11-18 색 면적·시각 위계 재설계(R1·R2): 사용자가 오렌지 대표 면을 거절하고 디자인 재검토를 요청했다. 이 항목이 아래 브랜드 강조 기준보다 우선한다.

- 연구: [McGill의 시각 위계 원칙](https://www.mcgill.ca/web-services/resources/toolkits/digital-design-toolkit/design-principles/visual-hierarchy)은 위치·크기·색의 상대적 차이를 설명한다. [Eater의 개편 설명](https://www.eater.com/editor-newsletter/883816/eater-has-a-new-look)과 [Eater](https://www.eater.com/)·[The Infatuation](https://www.theinfatuation.com/)·[Bon Appétit](https://www.bonappetit.com/)의 실제 화면을 새로 열고 캡처했다. 음식 사진과 큰 제목, 흰 여백에 제한한 브랜드 색을 참고하며 광고·쿠키 배너·다단 뉴스 배치는 적용하지 않는다. 캡처: 로컬 `web/data/ui-color-study/`.
- 색 계획: 흰 바탕 `#FFFFFF`, 음식명·주 행동의 토마토 레드 `#C93135`, 기본 글자 `#252525`, 설명 `#383C40`, 안내 `#60656B`, 목록 바탕 `#F5F6F7`. 기존 로고의 오렌지는 원본 자산으로 보존한다. 레드는 넓은 배경이 아니라 대표 제목·주 버튼·선택 상태에 사용한다.
- 타이포: Pretendard 유지. 대표 음식명은 모바일 40px·PC 72px/800, 태블릿은 48px. 설명 18px/1.75, 안내 14px를 유지한다. 글자와 사진의 크기 차이로 대표와 목록의 위계를 만든다.
- 배치: `흰 헤더 → [오늘의 음식 / 큰 레드 음식명 / 설명·행동 | 넓은 음식 사진] → 추천·출처 → 기존 탐색·목록`. 왼쪽 정렬, PC 43:57 분할과 40px 간격, 모바일 사진→설명. 둥근 색 배너·이중 사진 프레임은 제거하고 사진만 8px 모서리로 표시한다. 목록은 PC 2열·모바일 1열·세 번째 PC 전체 너비를 보존한다.
- 초안 검토: 배너 색만 바꾸는 안은 제외했다. 전체 면을 채운 색이 음식과 경쟁한 점을 고치고, 실제 음식명 자체를 서비스의 인상으로 삼는다. 전체를 흰색·같은 크기 글자로만 만드는 안도 제외하고, 레드의 쓰임을 제목·행동·선택으로 정한다. 설명 생략·장식 배지·새 슬로건·자동 재생은 추가하지 않는다.

2026-11-18 브랜드 강조(R1·R2): 사용자가 가독성뿐 아니라 서비스를 기억하게 하는 강조를 요청했다. 이 항목이 이전 흰 대표 영역 기준보다 우선한다.

- 색 계획: 로고 원본 오렌지 `#FF6B0A`를 대표 음식의 큰 면에 사용한다. 먹색 `#252525`는 큰 음식명·대표 버튼, 흰색 `#FFFFFF`는 사진 프레임, 목록 `#F5F6F7`·본문 `#383C40`·안내 `#60656B`는 기존 가독성 기준을 유지한다. 브랜드 강조는 대표 음식에 집중한다.
- 구성: `흰 헤더 → [오렌지 설명 / 흰 프레임의 음식 사진] → 추천·출처 안내 → 가로 탐색·기존 목록`. 모바일은 사진→음식명/설명/버튼 순서를 보존한다. 대표 면은 24px 모서리, 사진은 흰 프레임 안에 두어 오렌지와 음식의 경계가 눈에 들어오게 한다.

## 6. 사진
- **비율:** 목록 카드 3:2 (`aspect-[3/2] object-cover`), 영상 16:9, 히어로는 영역을 꽉 채움(`object-cover`).
- **히어로 그라데이션 (글자 가독성):** 위에서 아래로 `scrim` 55~60% → 0%(28~30%) → 0%(38~40%) → 86~88%(바닥). 헤더와 제목이 모두 사진 위에 흰 글자로 올라간다.
- 사진이 늦게 뜰 때 바탕은 `secondary`. `next/image`에 `width`·`height` 또는 `fill` + `sizes`를 반드시 지정해 CLS를 막는다.
- 대체 텍스트는 "무엇이 어떻게 담겼는지" 한 문장 (예: "새우와 떡이 들어간 주황빛 로제 떡볶이"). 장식용 사진은 `alt=""`.
- 생성 이미지는 상세에서 `AI 생성 예시`로 구분하며 대체 설명에도 생성 사실을 유지한다(2026-11-18 변경). 메인 사진 유형 배지는 표시하지 않는다. 실사 사진은 상세 화면 사진 아래에 `사진: 출처 · 라이선스` 를 13px 로 표시한다.
- 지금 들어 있는 사진(`web/src/assets/demo/`)은 데모용. 실서비스 사진 조건은 `docs/spec.md` Design의 사진 절.

## 8. 접근성·동작
- 포커스: 3px `ring` 실선, 2px 띄움 (`:focus-visible`).
- 터치 영역 44×44px 이상. 아이콘만 있는 버튼은 `aria-label`.
- 상단 칩 줄은 `nav aria-label="정렬과 필터"`, 브레드크럼은 `nav aria-label="현재 위치"`.
- 진행 막대에 `aria-valuenow`/`aria-valuemax`, 그래프에 텍스트 설명.
- `prefers-reduced-motion`이면 전환 효과를 끈다. 기본 전환은 150ms 이하, 색·투명도만.
- 검증: Playwright 390px·1280px 스크린샷 + axe 위반 0건.
