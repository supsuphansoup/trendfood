# Spec: 유행 레시피 × 재료 커미션 서비스

Status: draft. `docs/intent.md`(draft) 기준 초안이며 코드는 없다. `docs/questions.md`의 결정이 나오면 다시 작성한다.

## Requirements
MVP 기준. ID(R1…)는 plan.md와 테스트에서 참조한다.

### 콘텐츠
- R1 운영자가 레시피를 등록·수정할 수 있다: 이름, 한 줄 설명, 기본 인분, 재료 목록(이름·양·단위·연결 상품), 조리 단계(글), 원작 출처.
- R2 레시피 페이지는 글 위주로 보여 준다: 대표 사진은 최대 1장(임시), 조리 단계는 번호 붙은 텍스트 목록.

### 탐색
- R3 첫 화면에 "지금 유행" 순위를 보여 준다.
- R4 첫 화면에 좋아요 순위를 보여 준다.

### 레시피 · 재료 · 구매
- R5 인분을 바꾸면 모든 재료 양이 비례해 다시 계산된다.
- R6 재료마다 "필요(구매)" 체크를 할 수 있다. 기본값은 해제 — 집에 없는 것만 체크한다.
- R7 체크한 재료마다 구매 개수(상품 단위)를 정할 수 있다. 기본 1개.
- R8 "장바구니에 한 번에 담기" 버튼 한 번으로, 체크한 재료의 연결 상품이 정한 개수만큼 제휴 쇼핑몰 장바구니에 담긴다. (Q1 결과에 따라 대체 동작 — Areas of concern 1)
- R9 구매 버튼 바로 옆과 페이지 하단에 수수료 표기 문구를 보여 준다.

### 커뮤니티
- R10 로그인 없이 레시피에 익명 리뷰를 남길 수 있다.
- R11 로그인 없이 레시피에 좋아요를 누를 수 있고, 좋아요 수가 좋아요 순위에 반영된다.

### MVP 제외 (명시)
회원가입·로그인, 유저 본인 댓글 삭제(출시 후 공지하고 추가), 구독, 영상, 다크모드.

## Design

### 화면 구성
| 화면 | 내용 |
| --- | --- |
| 첫 화면 | 유행 순위, 좋아요 순위. 항목마다 순위·이름·한 줄 설명·좋아요 수 |
| 레시피 상세 | 이름·설명·인분 선택 → 재료 목록(체크·양·구매 개수) → 장바구니 버튼 + 수수료 표기 → 조리 단계 → 좋아요 → 익명 리뷰 목록·작성 |
| 운영(레시피 등록) | 방식 미정 — 관리자 화면 vs 데이터 파일 직접 편집 (Q3, Q15) |

### 규칙과 수치 (전부 AI 임시값 — Areas of concern 7)
- 인분: 레시피별 기본 인분에서 시작, 범위 1~10인분, 1인분 단위.
- 양 계산: 기본 양 × (선택 인분 ÷ 기본 인분). 소수 첫째 자리까지 표시. "약간·적당량" 같은 비수치 양은 그대로 둔다.
- 구매 개수: 1~10개. 인분을 바꿔도 자동으로 바뀌지 않는다 (레시피 사용량과 상품 단위가 다르기 때문 — Areas of concern 2).
- 유행 순위: 운영자가 주 1회 수동 갱신, 상위 10개 노출.
- 좋아요 순위: 누적 좋아요 수 내림차순, 동점이면 최근 등록 순, 상위 10개 노출.
- 좋아요: 브라우저 기준 레시피당 1회.
- 익명 리뷰: 1~300자, 작성자 이름 없이 작성 시각만 표시, 최신순 정렬.
- 수수료 문구(임시): "이 페이지의 구매 링크로 구매하시면 운영자가 일정 수수료를 받을 수 있습니다." 최종 문구는 제휴사 규정 확인 후 확정.
- 첫 화면은 모바일에서 2초 안에 표시.

### 동작 흐름
1. 첫 화면 → 순위에서 레시피 선택
2. 상세에서 인분 선택 → 재료 양 갱신
3. 집에 없는 재료 체크 → 구매 개수 조정
4. 장바구니 버튼 → 제휴 쇼핑몰 장바구니가 새 탭으로 열리고, 선택한 상품이 담긴 상태
5. 사용자가 구매하면 제휴사 쪽에서 커미션이 추적된다

## Areas of concern
★ 사람이 가장 먼저 보고 결정할 것.

1. **장바구니 일괄 담기(R8)가 제휴사에서 안 될 수 있다.** 일반 제휴 링크는 상품 1개 단위인 경우가 많다. 안 되면 대안: (a) 재료별 구매 링크 목록 (b) 묶음 상품·밀키트 링크 (c) 장보기 목록 복사·공유. 대안으로 가면 "원클릭"이 핵심 가치에서 빠지므로 intent부터 고쳐야 한다. (Q1)
2. **레시피 사용량 ≠ 구매 단위.** "간장 2큰술"이 필요해도 상품은 "500ml 1병"이다. 그래서 구매 개수를 인분과 분리했고, 재료마다 운영자가 상품 1개를 연결한다고 가정했다. 품절·가격 변동 처리는 아직 없다. (Q11)
3. **익명 리뷰인데 삭제 기능은 출시 후.** MVP 기간에 욕설·스팸·광고 리뷰를 막을 수단이 없다. 운영자 삭제는 MVP에 넣고, 메모의 "댓글 삭제(출시 후)"는 유저 본인 삭제로 볼지 결정이 필요하다. (Q14)
4. **좋아요 조작.** 로그인 없이 브라우저 기준 1회면 쉽게 중복된다. 좋아요 순위에 바로 반영되므로 영향이 있다. (Q14)
5. **글 위주 vs 바이럴 이미지.** 레시피 페이지는 사진을 줄이는데, 바이럴 제안(순위 이미지 공유·숏폼 카드)은 이미지가 필요하다. 공유용 이미지를 별도 기능으로 볼지 정해야 한다. (Q6)
6. **레시피 출처·저작권.** 유행 레시피는 대부분 원작자(유튜버·블로거 등)가 있다. 옮겨 적을 때 출처 표기와 문장 재작성 기준이 필요하다. (Q3)
7. **AI가 임의로 정한 수치:** 인분 1~10, 순위 10개·주 1회 갱신, 리뷰 300자, 구매 개수 1~10, 첫 화면 2초, 대표 사진 1장, 체크 기본값 해제. (Q10, Q13, Q14)
8. **수수료 표기 문구·위치는 임시.** 제휴사별로 필수 문구가 따로 있을 수 있다. (Q2)
