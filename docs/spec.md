## Requirements

### 방문자 화면
- R1 ✅ **메인 `/`**: 1위 사진 히어로(헤더가 사진 위에 겹침) → 카테고리 탭 → 정렬·태그 칩 → 2위부터 한 줄에 하나씩 큰 사진 카드 → 4위 다음 인피드 광고 1개 → "11위부터는…" 안내. 맨 위로 버튼.
- R2 ✅ **필터**: 카테고리(전체·디저트·밥·면·분식·간식·찜), 정렬(급상승순·좋아요순·조리시간순), 태그(10분컷·자취생·디저트·안주), 음식명·재료 검색(지우기 버튼). 상태는 주소 `?cat=&sort=&tag=&q=` 에 남아 뒤로가기·공유가 된다.
- R3 ✅ **찜**: 로그인 없이 브라우저 저장(`tf:likes`), 헤더 "찜 N" 이 찜 탭으로 이동.
- R4 ✅ **상세 `/food/[slug]`**: 사진 히어로, 왜 뜨는지(AI 요약 표시 + 14일 검색량 그래프), 편의점·마트 버전, 단계별 조리법 + 단계 타이머, 조리법 아래 광고 1개.
- R5 🟡 **원본 영상**: 지금은 자리만 있음. YouTube 공식 임베드 + 출처 크레딧, 원작자 요청 시 즉시 내림.
- R6 ✅ **재료 장바구니**: 기본 전체 선택, "집에 있어요" 기억(`tf:pantry`, 다음 레시피에도 적용), 핵심 재료 강조, **[다음 재료 담기] 탭 1회 = 쿠팡 상품 1개 새 창**, 진행 상태 기억(`tf:added:<slug>`), 목록 복사·공유, 모바일 하단 고정 바.
- R7 ✅ **대가성 문구**: 장바구니 상단·푸터·소개에 "쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." (조건부 표현 금지).
- R8 ✅ **필수 페이지**: `/about`(소개·개인정보처리방침·이용약관·연락처 구역), 404.

### 운영자 화면 `/admin`
- R9 ✅ 공개 화면에 링크 없음, `noindex` 메타 + `X-Robots-Tag`. Supabase 이메일 로그인, `admins` 표에 있는 계정만 데이터 접근.
- R10 ✅ **게시 관리**: 순서(위/아래), 숨기기, 게시/초안 전환, 글 고치기(한 줄 설명·요약·팁).
- R11 ✅ **재료 링크**: 재료마다 쿠팡 주소(쿠팡 도메인만)·참고 가격.
- R12 ✅ **후보 큐**: 자동 수집 후보 + 직접 추가, 승인(AI 초안이 있으면 `foods` 초안 행 생성)·반려.
- R13 ✅ **[사이트에 반영]**: 사이트 재빌드 요청 + 마지막 자동 수집 결과·실패 원인 표시.
- R14 ⬜ **대표 사진 선택**: 후보 사진 3~4장 중 선택 또는 업로드("AI 이미지" 표시).
- R15 ⬜ **삭제 요청 창구**: 원작자 요청 접수 → 게시물 내림 기록.
- R16 ⬜ **조리법·재료 목록 편집**: 단계·재료 추가/삭제/순서 (지금은 SQL 또는 초안 그대로).

### 자동화
- R17 ✅ **매일 수집**: YouTube 인기 음식 영상 제목 → LLM 음식명 추출 → 네이버 데이터랩 급상승 배수 → 후보 '대기' 저장, 상위 몇 개는 AI 상세 초안. 자동 게시는 하지 않는다.
- R18 ✅ **배포**: main push · [사이트에 반영] · 수동 실행 때 정적 빌드 후 Cloudflare Pages 업로드.
- R19 ⬜ **통계 갱신**: YouTube 에서 가져온 수치는 30일 안에 갱신 또는 삭제 (API 약관).
- R20 ⬜ **분석**: GA4 + 쿠팡 `subId` 로 글별 클릭·수익 추적.

- 이전 기획 v2.0→v2.1의 변경은 정보 우선·공식 API·운영자 승인·다음 재료 연속 담기·포토 피드형·후기 연기를 현재 규칙에 반영했다. 이전 원클릭 커머스·자동 게시·데모 코드 재사용은 제외한다.

## Design

### 시스템 구조
```
GitHub Actions pipeline (매일 21:00 UTC = 06:00 KST)
  └▶ YouTube search.list → LLM → 네이버 데이터랩 → Supabase candidates (service_role)
운영자 브라우저 /admin ──(anon 키 + 로그인 JWT, RLS)──▶ Supabase foods·ingredients·candidates
  └▶ [사이트에 반영] → Edge Function request-publish → GitHub repository_dispatch(publish)
GitHub Actions deploy → npm run build (published_foods 뷰 읽기) → out/ → wrangler pages deploy
방문자 ◀── Cloudflare Pages 정적 파일 (out/, 404.html, _headers)
```
- 사진은 DB에 **키 이름**(`dubai` 등)만 두고 파일은 빌드에 포함한다 (`web/src/lib/foods.ts`). Supabase 스토리지 전송량을 쓰지 않기 위해서.
- Supabase 가 설정되지 않으면 빌드는 `web/src/data/seed-foods.ts` 예시 10개로 만든다. 설정됐는데 게시 음식이 0개면 **빌드를 멈춘다** (빈 사이트 배포 방지).
- 기술·시각 스택은 `docs/intent.md` Constraints·`docs/design.md` 를 따른다. 기존 기획의 애니메이션 선택은 CSS 우선, 필요 시 Motion(LazyMotion) 검토였으며 새 패키지는 별도 승인 전 추가하지 않는다. `prefers-reduced-motion`을 존중한다.
- 월 고정비 가정은 Cloudflare Pages·Supabase Free·GitHub Actions(공개 저장소) + 이번 달 OpenAI 크레딧·이후 Gemini 무료 등급으로 도메인 외 약 0원. 무료 한도·약관 문제가 생기면 Supabase Pro $25부터 검토한다. LLM 공급자·전환은 현행 수집 규칙과 Open questions 3이 기준이다.

### 데이터 규칙 (DB 제약과 화면 검사가 같다)
| 항목 | 규칙 |
| :--- | :--- |
| slug | `^[a-z0-9]+(-[a-z0-9]+)*$` |
| 음식 이름 | 1~30자 |
| 한 줄 설명 / 요약 / 팁 | 200자 / 600자 / 300자 |
| 카테고리 | 디저트·밥·면·분식·간식 (그 외는 간식으로) |
| 난이도 | 쉬움·보통·어려움 |
| 조리 시간 | 1~1440분 |
| 재료 | 이름 1~60자, 음식당 이름 중복 금지, AI 초안은 최대 20개 |
| 쿠팡 주소 | `^https://([a-z0-9-]+\.)*(coupang\.com|coupa\.ng)(/|$)` |
| 참고 가격 | 0~10,000,000원 정수, 없으면 "집에 흔한 재료" |
| 후보 중복 | 같은 주(월요일 시작) 안에서 `normalized`(띄어쓰기·대소문자·`·-_` 무시) 중복 금지 |
| 순위 | `sort_order` 오름차순, 게시+숨기지 않은 것만 1위부터 번호 |

### 권한 (RLS)
- 방문자(anon): `status='published' and not hidden` 인 음식과 그 재료만 읽기.
- 운영자(`admins` 에 있는 로그인 계정): 모든 표 읽기·쓰기. `pipeline_runs` 는 읽기만.
- 수집 스크립트: `service_role` 키(GitHub Secret)로 RLS 우회. 브라우저·로컬에는 두지 않는다.
- 회원 가입은 Supabase 대시보드에서 끈다. 운영자 등록은 SQL Editor 에서만.

### 수집 규칙 (`web/scripts/pipeline/`)
| 항목 | 값 |
| :--- | :--- |
| 검색어 | "요즘 유행 음식, 유행 디저트 만들기, 편의점 신상 디저트, 자취 요리 유행, SNS 화제 레시피" (`PIPELINE_QUERIES`) |
| 영상 | 최근 7일, 한국·한국어, 조회수순, 검색어당 25개 (search.list 100유닛 × 5 = 하루 500유닛) |
| 급상승 배수 | 최근 3일 평균 ÷ 그 앞 11일 평균 (14일 일별 데이터), 앞 기간이 0이면 최근값(최대 99) |
| 점수 | 배수 × (1 + log2(언급 수)) |
| 후보 조건 | 배수 ≥ 1.3 (`PIPELINE_MIN_MULTIPLIER`), 이미 사이트·이번 주 후보에 있으면 제외, 최대 10개 |
| AI 초안 | 점수 상위 3개 (`PIPELINE_DRAFTS`), 6단계·재료 12개 이내, 주어진 수치·제목 외 사실 금지 |
| AI 공급자 | `AI_PROVIDER`(openai·gemini) + `AI_MODEL` 환경변수. 429 → "AI 크레딧·무료 한도 소진" 기록 |
| 키 없을 때 | 그 단계만 예시 값, Supabase 키 없거나 `--dry-run` 이면 DB 에 쓰지 않음 |

DataLab은 **입력한 키워드의 추이만** 반환하므로 후보 찾기와 점수 매기기를 나눈다. 운영자 시드 키워드를 보충하며, 오픈 직후에는 운영자가 후보를 직접 입력하고 점수만 자동으로 돌려도 된다. 수집은 GitHub Actions 하루 1회이며 AI 초안은 운영자가 10~20분 검수한 뒤 게시한다.

| 소스 | 역할·제약 |
| :--- | :--- |
| 네이버 DataLab / API HUB | 상대지수로 급상승 감지. 이전 기획에는 API별 월 50,000건·한시 무료, 2026-07-31부터 신규는 API HUB 발급으로 기록됨; 현재 주소·한도는 Areas of concern 및 plan Risks 확인 |
| 네이버 검색광고 API | 절대 검색량으로 저볼륨 노이즈 제거·연관 키워드. 광고주 계정 + API 매니저 발급 필요, 쉬운 수집 안정 후 도입 |
| 네이버 블로그·카페 검색 | API HUB의 글 수 증가 신호, 쉬운 수집 안정 후 도입 |
| YouTube Data API v3 | 근거 영상 탐색·통계. 현재 검색 수치·쿼터 계산은 위 표가 기준; 확장 시 `publishedAfter`·`regionCode=KR`, `playlistItems.list`로 요리 채널 화이트리스트 업로드 폴링, `videos.list`로 통계 갱신 |
| Instagram / TikTok | 운영자가 URL을 등록하는 **공식 임베드 전용**, 수집·분석·게시물 사진 저장·재사용 금지 |
| Instagram (Phase 2 검토) | Graph API 해시태그 검색을 급상승 **보조 신호**로만 검토. 비즈니스 계정 + Meta 앱 심사 'Instagram Public Content Access' 필요. 이전 기획 한도는 7일간 해시태그 30개, 최근 게시물 24시간·250개이며 도입 전 재확인 |
| 운영자 | TikTok Creative Center 등 주 1회 수동 확인 → 키워드 보충 |

- LLM 입력은 영상 제목·설명란·태그 + 운영자 메모만; 자막·음성은 추출하지 않는다. `captions.download`는 영상 소유자만 가능하다.
- SNS·커뮤니티(에펨코리아·디시·더쿠 등) 크롤링, YouTube 스크래핑, YouTube 수치로 만든 자체 급상승 점수의 화면 노출은 하지 않는다. 점수는 내부 정렬 전용, 화면에는 원본 수치를 출처와 함께 표시한다.
- 확장안은 DataLab 상대지수를 기준 키워드로 정규화 → 주간 증가율(log2) + z-score 혼합, 검색광고 절대 검색량이 일정 기준 미만이면 제외. 가중치는 운영 데이터로 보정하며, 현재 구현의 점수·배수는 위 표를 유지한다.

### 화면 구성
| 영역 | 구성·남은 차이 |
| :--- | :--- |
| 메인 | 히어로 근거 한 줄·레시피 보기·재료 담기, 헤더 로고·통합 검색·찜·제휴 안내. 순위 카드는 순위 변동(새 진입·상승/하락·그대로)·한 줄 설명·조리시간·찜 수·레시피 보기·재료 n개 담기. 기존 난이도 필터 요구는 미구현. 카테고리·태그·정렬·10개 이후 안내는 R1·R2가 최신 기준 |
| 상세 | '순위로' 뒤로가기·브레드크럼·음식명·소요시간·난이도·인분·찜/공유, AI 요약·근거 영상, 편의점·마트 버전(해당 시), 조리법·타이머·팁. PC 좌 장바구니 5 : 우 내용 7, 모바일 큰 체크박스·하단 CTA (`docs/design.md` 4·7장) |
| 장바구니 | 미리 매칭한 상품명·참고 가격·선택 개수·합계·가격 기준 시각. 사용자가 쿠팡에서 돌아오면 완료 개수와 다음 재료를 보여주고 마지막에 장보기 완료. 기존 요구의 가격 문구는 "가격 기준 시각, 실제 가격과 다를 수 있음"이며 현행 표시는 Open questions 5 참고 |
| 공유 | 재료 목록 복사·공유(R6). 카카오톡 공유는 기존 요구로 남아 있으며 전용 연동은 아직 없음 |
| 푸터 | 소개·개인정보처리방침·이용약관·연락처·쿠팡 파트너스 고지(R7·R8) |
| 광고 슬롯 | 메인 4위 다음 1개, 상세 조리법 하단 1개. 높이를 미리 확보해 CLS 방지, 페이지 이동 시 재로드 처리 |

기존 단일 파일 데모는 배치 참고용이었다. 실제 화면은 Next.js + Tailwind + shadcn/ui로 새로 구현하며 데모 HTML/JS·목업 데이터·반응형 테스트 툴바·원클릭 장바구니 모달은 재사용하지 않는다. 실제 화면(`web/`) + `docs/design.md` 가 시각 기준이고 예전 시안은 `archive/design-mockups/` 에 보관한다.

| :--- | :--- |
| 쿠팡 링크 (오픈 ~ 콘텐츠 20~30개) | 가입 즉시 생성 가능한 파트너스 링크를 운영자가 재료별 수동 등록 |
| 애드센스 신청 | 직접 작성·검수한 글 20~30개 이상, 자체 도메인·개인정보처리방침·소개·연락처. AI 대량 생성 페이지 금지, 승인 후 `ads.txt` 배포 |
| 쿠팡 API | **누적 판매 15만원 + 최종 승인 후** 상품 검색·딥링크 자동화, 레시피별 `subId` 성과 추적 |
| 향후 검토 | 브랜드 협찬 / 트렌드 리포트는 트래픽·데이터 축적 후, MVP 제외 |

- 광고는 본문(레시피) 하단·카드 사이 인피드, 페이지당 1~2개로 시작. 사이드바 광고와 장바구니 CTA·"다음 재료" 버튼·재료 체크리스트 주변 광고, 클릭 유도 문구는 금지한다.
- 자동 광고(Auto ads)는 모바일 레시피 가독성을 해치지 않는지 확인한 후에만 사용한다.
- 수익 가정(보장 아님): 주문당 약 450~1,500원(장바구니 3~5만원 × 식품 요율 1.5~3%), 첫 링크 클릭 후 **24시간 내 쿠팡에서 산 다른 상품도 실적 인정**. 애드센스는 1,000PV당 약 1,000~5,000원, 월 10만 PV ≈ 월 10~50만원. 식품 공식 수수료율은 확인 전이다.

### 사진
자체 촬영 / 사람이 검수한 AI 생성("AI 이미지" 표시) 우선, 무료 사진은 보조. 유행 음식은 무료 사진에 거의 없으므로 운영자가 후보 중 고른다(R14). 플랫폼 썸네일·SNS 게시물 사진 저장·재사용 금지, 상표·포장지 로고·사람 얼굴이 크게 나온 사진은 피한다.

| 출처 | 라이선스·주의 |
| :--- | :--- |
| Unsplash | 상업 무료, **API 사용 시 작가·Unsplash 표시와 API 이미지 URL 사용 의무** |
| Pexels·Pixabay | 상업 무료, API의 출처 표시·저장·핫링크 조건은 공식 약관 확인 필요 |
| 공유마당·공공누리 1유형 | 출처 표시 시 상업 가능, 한식에 강함. 사진마다 라이선스 확인 |
| Wikimedia Commons | **CC0·퍼블릭 도메인만** |
| 예전 시안 사진 | `archive/design-mockups/img/`·`credits.json` 은 데모용, **실서비스 사용 금지** |

이미지는 sharp로 미리 WebP 변환해 서빙하되 API 출처별 조건을 먼저 따른다. 빌드에 포함하는 현행 구조는 시스템 구조 참고; Unsplash API 이미지 URL 조건과 저장 방식은 R14 도입 때 확인한다.

### 화면 수치
- 기준 폭: 모바일 390px, PC 1280px (최대 1200px 본문). PC는 왼쪽 고정 카테고리 탭, 모바일은 상단 가로 탭.

## Areas of concern (사람이 먼저 보고 결정할 것)
1. **AI가 정한 수치**: 배수 기준 1.3, 초안 3개, 영상 7일·검색어 5개, 점수 공식, 반영 쿨다운 5분, 수집 시각 06:00. 실제 데이터로 1~2주 돌려 보고 조정 필요.
2. **초안 사진**: 승인된 AI 초안은 사진이 정해지지 않아 임시로 `dubai` 사진 키가 들어간다. R14 전에는 **게시 전에 운영자가 사진을 바꿔야** 하는데, 지금 관리자 화면에는 사진 바꾸기가 없다 (SQL 로만 가능).
3. **조리법·재료 편집 불가**: 관리자 화면에서 단계·재료를 추가/삭제할 수 없다 (R16). AI 초안이 틀리면 고치기 어렵다.
4. **네이버 데이터랩 주소**: 기존 `openapi.naver.com/v1/datalab/search` 를 쓴다. "API HUB" 로 옮겨 가면 `NAVER_DATALAB_URL` 만 바꾸면 되지만, 새 주소·요청 형식은 미확인.
5. **무료 등급 위험**: Supabase Free 는 1주 무활동 시 정지(매일 수집이 막아 줌), 무료 등급의 상업 이용 조항 불명확. GitHub Actions 예약은 공개 저장소에서 60일 무커밋 시 정지.
6. **YouTube 약관**: 상세의 "관련 영상 n개" 와 후보 근거에 YouTube 에서 온 수치가 들어간다. "자체 파생 지표 노출 금지·30일 갱신" 조항에 맞는지 확인 필요 (R19).
7. **실제 연결 미검증**: Supabase·Edge Function·Cloudflare 배포는 테스트에서 가짜 Supabase·PGlite 로만 확인했다. 첫 실제 연결 때 `ONBOARDING.md` 7-5 로 확인.
8. **관리자 화면 공개성**: 정적 사이트라 `/admin` 화면 자체는 누구나 열 수 있다 (데이터는 RLS 로 보호). 주소를 숨기는 것은 보안이 아니라 편의다.
9. **수익·API 약관 미확인**: 쿠팡 API 실제 호출 한도(분당 50회 vs 시간당 10회, 출처 충돌)·식품 공식 수수료율, 네이버 API HUB 유료 전환 시점·단가·검색광고 API 비광고 목적 사용 약관을 확인한다. 이전 기획의 DataLab 월 50,000건·YouTube 검색 하루 100회(별도 쿼터)와 현행 spec·plan 수치는 다르므로 최신 문서를 유지하고 실제 적용 전 공식 한도를 확인한다.
10. **법·검색 노출 미확인**: 운영자 검수 게시 시 AI 기본법 표시 의무의 세부 범위, 사업자 신고(Open questions 6), 한국의 Google 레시피 리치 결과 노출 여부.
11. **무료 LLM·외부 콘텐츠**: Gemini 무료 한도·학습 사용·상업 이용(Open questions 3), Pexels·Pixabay API 출처 표시·이미지 저장·핫링크 조건, Instagram Public Content Access 앱 심사의 소규모 신규 사이트 통과 가능성과 현재 해시태그 검색 한도. 도입 전 공식 문서로 재확인한다.
