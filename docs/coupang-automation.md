# 쿠팡 재료 링크 자동 연결

팀장의 2026-11-12 요청으로 기존 음식과 새 음식의 링크가 없는 재료를 자동 검색·대조·연결하도록 준비했다. 현재 저장소에서 쿠팡 API 키·채널 ID를 확인하지 못했으므로 실제 계정의 제휴 링크 발급과 수익 귀속은 검증 전이다. 일반 쿠팡 검색 주소를 제휴 링크라고 표시하거나 임의 추적 값을 붙여 수익을 주장하지 않는다.

현재 운영 상태(2026-11-12): 파트너스 승인을 받지 못했다는 팀장 안내에 따라 제휴 자동화는 `PIPELINE_AUTO_COUPANG=false`로 중지했다. 승인 전에는 아래 일반 상품 상세주소 검색을 사용한다. 제휴 자동화 재개는 계정 연결 순서를 따른다.

## 승인 전 일반 상품 상세주소

`PIPELINE_AUTO_PRODUCT_LINKS=true`이면 기존 매일 10:17 KST 자동화에서 링크 없는 재료를 최대 5종 검색하고, 재료 대조를 통과한 일반 쿠팡 상품 상세주소를 저장한다. 파트너스 승인·키 없이 동작하며 제휴 수익은 없다. 상품을 찾지 못하거나 대조에 실패하면 기존 재료명 검색 연결을 유지한다. 기존 링크는 보존하므로 승인 후 제휴 URL로 바꾸려면 해당 재료 URL을 비우거나 직접 교체한다.

[OpenAI 공식 웹 검색 API](https://developers.openai.com/api/docs/guides/tools-web-search)의 `web_search`를 사용한다. 도메인은 `www.coupang.com`, `external_web_access=false`로 제한해 검색 색인만 사용하고 쿠팡 페이지를 직접 수집하지 않는다. 완료된 검색의 `sources`에 있는 URL과 인용 제목이 함께 있는 상품만 후보로 삼는다. AI 본문에 적힌 주소는 사용하지 않는다. HTTPS `www.coupang.com/vp/products/<상품 ID>`와 실제 선택 옵션 `itemId`·`vendorItemId`만 보존하고 유입 추적 값은 제외한다. 일반 상품 자동 연결에는 출처 URL의 `itemId`가 필수이며 옵션 ID를 추측해 붙이지 않는다. 이후 아래의 동일 재료·용량 대조 기준을 적용한다.

현재 설정된 OpenAI 모델·키를 사용하며 검색 도구와 AI 대조 비용이 기존 OpenAI 계정에 발생한다. 다른 공급자로 바꾸거나 키가 없으면 건너뛴다. 검색은 응답당 도구 최대 1회, 실행당·시간당 최대 5회로 제한하고 실패·미리보기 호출도 기록한다. 제휴 자동화를 켜면 이 단계는 건너뛴다. 이 한도는 다른 도구의 사용량까지 제한하지 않는다.

검색 색인은 오래된 페이지일 수 있다. 상품의 현재 판매 여부·옵션·가격·재고를 검증하는 기능은 없으며 실제 구매 전 쿠팡에서 확인해야 한다. 일반 상품 검색 기록은 `web/data/product-link-state.json`, 실행 결과는 `automation-report`의 `product-link-report.json`에 저장한다. 아래 제휴 호출 기록과 별도 캐시를 사용하며 오류·캐시 유실·보류 처리는 같은 원칙을 따른다.

```bash
cd web
npm run links:auto -- --web-products --dry-run
npm run links:auto -- --web-products
```

## 연결 순서

1. [쿠팡 파트너스](https://partners.coupang.com/) 계정에 운영 사이트 `https://trendfood.pages.dev`와 활동 매체를 등록하고, 계정의 API 이용 권한을 확인한다. 공식 이용 가이드(2024년 12월판, 32~33쪽)는 최종 승인 후 API 키 발급을 안내한다. 현행 계정의 메뉴·승인 조건은 로그인 후 확인한다. 판매자용 WING API 키와 구분한다.
2. GitHub 저장소의 Settings → Secrets and variables → Actions → Secrets에 `COUPANG_ACCESS_KEY`, `COUPANG_SECRET_KEY`를 각각 등록한다. 키를 채팅·소스·로그에 보내지 않는다.
3. Variables에 계정에 등록한 채널 ID를 `COUPANG_SUB_ID`로 등록한다. 허용 형식은 영문·숫자·밑줄·하이픈 1~50자다. 이 형식 검사가 파트너스의 채널 등록을 확인해 주지는 않는다. 음식별 slug를 미등록 채널 ID로 만들지 않는다.
4. `PIPELINE_AUTO_COUPANG=true`로 켠 뒤 `pipeline`을 `links_only=true`로 한 번 실행해 실제 응답과 연결 상품을 확인한다. 통과한 URL 변경도 전체 검사를 거쳐 커밋·배포된다. `false`로 링크 자동화만 중지한다.

## 제휴 자동 처리

- 매일 10:17 KST의 기존 수집 뒤 링크 없는 재료를 모은다. 동일 이름의 재료는 한 번 검색하되 음식별 필요량에 따라 다른 포장을 연결할 수 있다. 최근 검색한 재료를 뒤로 보내 미발견 재료도 순환한다. `또는`·`혹은`·슬래시가 있는 복수 선택 재료는 보류한다.
- 필요량은 g/kg·ml/L·개수로 구분한다. 상품 제목에서 확인한 단위 용량과 포장 수량을 곱해 총량을 비교한다. 필요량보다 작은 상품은 제외하고, 같은 단위의 작은 포장부터 최대 3개를 대조한다. `약간`·큰술·범위·추가 사용량, 용량 미표기·복수 옵션·혼합 세트는 추측하지 않는다. 필요량이 불명확하면 유료 검색 없이 순환만 기록한다.
- 가정용 과대 포장 방지 기준은 질량·부피의 경우 `max(500g 또는 500ml, 필요량×3)`, 개수는 `max(10개, 필요량×3)`다. 이를 넘거나 업소용·대용량·벌크로 표시된 상품은 제외한다. 이 수치는 운영상 정한 보수적인 기준이다. 예를 들어 70g 필요 시 5kg은 제외하고 100g·200g·500g 순으로 검토한다.
- 실제 검색 목록 최대 10개 중 정확한 재료 이름을 포함하고 명백한 비식품이 아닌 상품에 용량 기준을 적용한다. 후보 구성이 같은 음식끼리 기존 AI 공급자·모델로 대조하며, 재료별 최대 3회·전체 최대 15회다. 모든 해당 조리 문맥에서 같은 식재료·식품이어야 하며 유효한 후보 인덱스와 0.95 이상·1 이하의 유한 신뢰 응답이 필요하다. 이 수치는 실제 정확도 보장이 아니다. 혼합물·다른 재료·용도·염분·당류 등이 불명확하면 연결하지 않는다. 성분·용도가 맞는 후보 중 남는 양이 적은 포장을 우선하도록 요청한다.
- 선택 범위는 검색으로 확보한 후보 안이다. 쿠팡 전체의 최적 상품·최저가를 보장하지 않으며, 이름 표현 차이로 적합한 상품을 놓칠 수도 있다. 적절한 후보가 없으면 기존 검색 연결을 유지한다.
- API가 반환한 상품별 `productUrl`만 저장한다. 검증한 HTTPS 쿠팡 제휴 호스트·상품 경로만 허용하고 검색 랜딩 주소·다른 상품 ID·다른 채널의 명시적 추적 값은 거절한다. 원본 주소를 조작하거나 AI가 만든 주소를 쓰지 않는다. 상품 검색 응답 자체에 제휴 URL이 있어 별도 딥링크 변환 API를 중복 호출하지 않는다.
- 기존 수동·자동 링크와 조리법·출처 확인 날짜를 보존한다. 상품명·ID·제휴 URL과 보류 이유는 실행 보고서로 확인하고, 공개 콘텐츠에는 재료 URL만 추가한다. 상품 가격·상품 사진은 저장하지 않는다. 기존 클릭 1회에 링크 하나를 여는 동작과 대가성 문구를 유지한다.
- 품절·판매 종료·기존 링크 유효성을 주기적으로 재검사하는 기능은 이번 범위에 없다. 교체할 때 해당 재료의 URL을 비우면 다음 순환 검색 대상이 된다. 실제 가격·옵션·재고는 이동한 쿠팡 페이지에서 확인한다.

## 한도·실패·기록

공식 이용 가이드 33쪽의 검색 시간당 최대 10회보다 낮은 **이 자동화의 시간당 최대 5회·실행당 최대 5회**로 제한한다. 계정의 다른 도구가 쓴 호출은 알 수 없으며, 이 제한이 계정 전체 호출량을 보장하지 않는다. 현행 계정의 한도가 더 낮으면 운영 전에 조정해야 한다. 자동 재시도나 다른 엔드포인트로의 재시도를 하지 않는다.

`web/data/coupang-state.json`에 검색 직전 시각·재료별 마지막 확인 시각·중단 종료 시각을 원자적으로 기록하고 GitHub Actions cache로 다음 실행에 전달한다. 실패·`--dry-run`도 실제 검색 횟수에 포함한다. 로컬 실행과 다른 도구의 호출 기록은 Actions와 자동 공유되지 않는다. 캐시 삭제·유실·퇴출 시 기록이 복원되지 않을 수 있으므로 연속 수동 재실행을 피하고 마지막 실행 후 한 시간을 기다린다. 동시에 실행한 별도 로컬 프로세스의 한도를 조정하는 기능은 없다.

HTTP 401·403·429·기타 오류, 비정상 JSON·API 실패 본문·연결 오류, AI 대조 실패 시 이번 실행의 추가 검색을 중단한다. HTTP 403·429 또는 응답 코드 429면 최소 24시간 중단 기록을 남긴다. 인증·API 응답 원문·헤더·키는 로그에 남기지 않는다. 앞에서 대조를 통과한 URL만 반영 가능하며 나머지는 기존 상태를 유지한다. 키·등록 채널 전체가 없으면 `skipped` 보고서를 남기고 공개 콘텐츠를 바꾸지 않는다. 일부만 설정했거나 호출 기록이 손상됐으면 실행을 실패시킨다.

`automation-report` 아티팩트의 `coupang-report.json`을 14일 보관한다. `accepted`는 상품명·ID·발급 URL·연결 재료 수, `deferred`는 보류 이유, `remaining`은 다음 순환 대기 건수다. `--dry-run`은 보고서와 실제 호출 기록만 저장하며 공개 JSON을 바꾸지 않는다.

```bash
cd web
npm run links:auto -- --dry-run
npm run links:auto
```

## 문서 확인·검증 범위

- [공식 파트너스 이용 가이드](https://partners.coupangcdn.com/partners-guide/partners-guide-20241202161107.pdf) 32~33쪽에서 상품·딥링크 API 제공, 키 발급 권한, 호출 제한을 확인했다. 다운로드한 원본은 Git 제외 `web/data/coupang-docs/official-guide.pdf`에 있다. 오래된 자료이므로 현행 한도·조건을 단정하지 않는다.
- [쿠팡 공식 HMAC 안내](https://developers.coupang.com/en/getting-started/creating-hmac-signature)에서 서명 형식을 확인했다. 판매자 API의 상품 엔드포인트를 파트너스 API로 혼동하지 않는다.
- 파트너스 포털의 API 문서는 이 실행 환경에서 Access Denied로 열리지 않았다. 상품 검색의 v1 경로·응답 구조는 [공개 클라이언트 저자의 API 참조](https://github.com/seungwonme/n8n-nodes-coupang-partners/blob/main/docs/coupang-api.md)와 해당 클라이언트의 구현을 대조했다. 이를 쿠팡 최신 공식 문서를 직접 확인한 것으로 표현하지 않는다. 계정 연결 후 공식 포털의 현행 경로·조건과 실제 응답을 반드시 확인한다. 응답이 다르면 실패 처리하며 임의의 대체 경로를 시도하지 않는다.
- 단위 검사는 서명 기준값·한도·호스트·상품 일치·수동 링크 보존·보류·순환·미설정 상태를 모의 응답으로 확인한다. 실제 파트너스 계정으로 발급·수익 정산까지 검증했다는 뜻은 아니다.
