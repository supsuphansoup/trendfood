# 크롤링을 버리고 공식 API로 트렌드푸드를 다시 짜기

TrendFood를 무리 없이 운영하려면 PRD의 "SNS·커뮤니티 크롤링 + 자막 LLM 파싱 + 쿠팡 원클릭 장바구니" 구조를 버려야 합니다. 대신 **"네이버 검색 신호로 키워드 감지 → YouTube 공식 API로 영상 탐색 → 설명란 텍스트만 LLM으로 구조화 → 사람 검수 → 재료별 쿠팡 딥링크"** 구조로 바꾸는 것이 핵심입니다. 이유는 세 가지입니다. 첫째, 공식 경로가 좁습니다. TikTok은 상업 서비스가 쓸 수 있는 탐색 API가 없습니다. Instagram 해시태그 검색은 7일 동안 고유 해시태그 30개로 묶여 있습니다. YouTube는 스크래핑과 타인 영상 자막 다운로드를 정책으로 막고 있습니다. 둘째, 쿠팡파트너스는 누적 판매 15만원을 넘겨 최종 승인을 받아야 API가 열립니다. 여러 상품을 한 번에 장바구니에 담는 공식 API도 확인되지 않았습니다. 셋째, 2026년 1월 시행된 AI 기본법은 LLM 생성 결과물에 표시 의무를 지웁니다. 2024년 12월 개정된 공정위 추천·보증 지침은 제휴 문구를 화면 상단에 두라고 요구합니다. 그래서 PRD의 크롤링 트랙, 자막 파싱, 다중 탭 장바구니, Vercel Hobby 운영 가정은 바꿔야 합니다. 바꾼 구성의 상업 운영 고정비는 **월 약 $47~65**(Vercel Pro + Supabase Pro + LLM)입니다. 핵심 데이터 API(네이버 API HUB, YouTube Data API)는 현재 무료입니다. 다만 네이버 HUB가 언제 유료로 바뀔지, 쿠팡 API의 실제 호출 한도가 얼마인지가 가장 큰 미지수로 남아 있습니다.

## 네이버가 감지하고, YouTube가 증명하고, 사람이 승인한다

트렌드 엔진의 1차 신호원은 네이버여야 합니다. 한국의 음식 검색은 네이버 비중이 높습니다. 네이버는 공식 경로로 상대 지수(DataLab), 절대 검색량(검색광고), 블로그·카페 포스트 수(검색 API)를 모두 얻을 수 있는 유일한 플랫폼입니다. 주의할 변경이 하나 있습니다. **2026-07-31부터 DataLab 신규 신청은 NAVER API HUB(NCP)로만 받습니다.** 기존 개발자센터 키는 2027-06-30까지만 지원되고 HUB 키와 호환되지 않습니다 ([digitalmarketer](https://www.digitalmarketer.co.kr/insights/naver-datalab-api-data-for-non-developers)). 따라서 처음부터 `naverapihub.apigw.ntruss.com` 엔드포인트로 구현해야 합니다. HUB 기준 한도는 검색어 트렌드와 쇼핑인사이트가 **각각 월 50,000건**이고 블로그·카페 등 검색 API는 **월 775,000건**입니다. 키당 50 RPS이며, 한도의 100%에 이르면 자동 차단됩니다. 지금은 "한시적으로 무료"이고 유료 전환 일정은 공지되지 않았습니다 ([NCP API HUB 개요](https://guide.ncloud-docs.com/docs/apihub-overview)).

DataLab ratio는 요청 안에서 최댓값을 100으로 둔 상대 지수입니다. 그래서 요청이 다르면 값을 직접 비교할 수 없습니다 ([digitalmarketer](https://www.digitalmarketer.co.kr/insights/naver-datalab-api-data-for-non-developers)). 매 요청에 고정 "앵커 키워드" 1개를 넣고 그 값으로 나눠 정규화해야 합니다. 급상승 판정에는 키워드별 자기 기준선 대비 지표를 씁니다. 7일 이동평균에 대해 WoW 로그비율과 28일 z-score를 계산합니다. 볼륨 하한(검색광고 `keywordstool` 월간 검색수)과 블로그 신규 포스트 수 z-score를 함께 걸면 "상시 인기"와 "급상승"을 구분할 수 있습니다. 이 가중치는 외부 벤치마크가 없는 설계 제안이므로 백테스트로 정해야 합니다. 검색광고 API는 광고주 계정에서 라이선스를 발급받아 HMAC 서명으로 호출합니다 ([naver/searchad-apidoc](https://github.com/naver/searchad-apidoc)). 광고 운영용으로 제공되는 API이므로, 그 검색량을 화면에 노출하지 말고 내부 랭킹 신호로만 쓰는 것이 안전합니다.

Google Trends는 보조 신호입니다. 공식 API는 2025-07에 alpha로 발표됐고 지금도 allowlist 신청제입니다 ([Google Search Central](https://developers.google.com/search/blog/2025/07/trends-api)). 비공식 pytrends는 2025-04에 아카이브됐습니다 ([apiserpent](https://apiserpent.com/blog/pytrends-dead-google-trends-data-2026)). 신청은 해 두되 파이프라인이 여기에 의존하면 안 됩니다. TikTok Creative Center는 공개 API가 없는 브라우저 UI입니다 ([Apify](https://apify.com/webdata_labs/tiktok-hashtag-trends-scraper)). 운영자가 눈으로 참고하는 용도로만 쓰는 것이 맞습니다.

### YouTube는 탐색 예산이 "하루 검색 100회"다

YouTube Data API는 2026-06-01부터 `search.list`를 별도 버킷으로 분리했습니다. **호출당 1단위, 하루 100회**입니다. `videos.list` 같은 나머지 메서드는 공용 10,000단위 버킷에서 호출당 1단위입니다 ([Quota calculator](https://developers.google.com/youtube/v3/determine_quota_cost), [Revision history](https://developers.google.com/youtube/v3/revision_history)). 그러니 검색은 귀하게 쓰고, 통계 갱신은 넉넉하게 해도 됩니다. 네이버에서 감지한 급상승 키워드와 고정 시드("자취요리", "레시피" 등)로 하루 약 80회 검색하고 20회는 예비로 남깁니다. 큐레이션한 한국 요리 채널은 uploads 플레이리스트(`playlistItems.list`, 1단위)로 폴링합니다. 후보 영상은 `videos.list` 50개 묶음으로 6~24시간마다 갱신해 조회수 증가율을 계산합니다. `chart=mostPopular`는 2025-07 Trending 페이지 폐지 이후 음악·영화·게임 차트 위주라서 음식 신호로는 쓸모가 거의 없습니다 ([Revision history](https://developers.google.com/youtube/v3/revision_history)).

PRD를 가장 크게 바꿔야 하는 곳은 레시피 입력원입니다. **`captions.download`는 영상 편집 권한이 있어야 하므로 타인 영상 자막은 공식적으로 받을 수 없습니다** ([captions.download](https://developers.google.com/youtube/v3/docs/captions/download)). Developer Policies는 YouTube 스크래핑과 API 외 수단으로 데이터를 얻는 것을 금지합니다(III.E.6, III.I.14). 비인가 데이터와 공개 통계는 30일 안에 갱신하거나 삭제해야 합니다(III.E.4.b/d). API 데이터로 "새 파생 데이터·메트릭"을 만드는 것도 금지합니다(III.E.4.h) ([Developer Policies](https://developers.google.com/youtube/terms/developer-policies)). 이를 반영하면 다음과 같이 설계해야 합니다. 첫째, LLM 입력은 공식 필드인 제목·설명란·태그로 한정합니다. 한국 요리 영상은 설명란에 재료가 적힌 경우가 많습니다. 설명란이 빈약하면 사람이 영상을 보고 작성합니다. 둘째, 바이럴 점수는 내부 정렬에만 씁니다. 셋째, 화면에는 YouTube 원본 수치를 출처와 함께 보여 주고, 자체 지표는 "TrendFood 자체 지표"로 표시합니다. 넷째, 영상 메타데이터와 통계 행은 30일 TTL로 갱신합니다.

### Instagram과 TikTok은 "임베드 전용"으로 강등한다

Instagram에서 타인 콘텐츠를 찾는 공식 경로는 두 가지입니다. 하나는 Hashtag Search이고(**7일 롤링 고유 해시태그 30개**, `top_media` 페이지당 50개, 조회수 필드 없음) ([IG Hashtag Search](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-hashtag-search), [top_media](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-hashtag/top-media)), 다른 하나는 사용자명을 아는 계정을 조회하는 Business Discovery입니다 ([Business Discovery](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery)). 둘 다 App Review와 자사 Business 계정이 필요합니다. oEmbed는 시간당 1,000건까지 쓸 수 있지만 표시 외 용도(분석 등)로 쓰는 것은 금지됩니다 ([Instagram oEmbed](https://developers.facebook.com/docs/instagram-platform/oembed)). 썸네일과 author 필드는 2025년에 응답에서 제거됐습니다 ([Meta dev blog](https://developers.facebook.com/blog/post/2025/04/08/oembed-updates/)). TikTok의 Research API는 "상업적 이해관계에서 독립된" 학술·비영리 기관 전용입니다 ([Research API](https://developers.tiktok.com/products/research-api/)). Display API는 로그인한 사용자 본인의 영상만 다룹니다 ([Display API](https://developers.tiktok.com/doc/display-api-overview)). 상업 서비스에 허용되는 것은 URL을 알고 있는 영상의 Embed Player(`/player/v1/{id}`) 임베드뿐입니다 ([Embed Videos](https://developers.tiktok.com/doc/embed-videos/)). 따라서 두 플랫폼은 다음과 같이 씁니다. MVP에서는 운영자나 사용자가 URL을 등록하고 임베드로 보여 주는 보조 채널로 둡니다. 확장 단계에서는 Instagram App Review를 거쳐 해시태그 슬롯을 운영하고 화이트리스트 크리에이터를 Business Discovery로 조회합니다.

커뮤니티 크롤링 트랙(에펨코리아, 디시, 더쿠, 뽐뿌)은 이번 조사에서 공식 API나 약관 허용 여부를 확인하지 못했습니다. 레시피 플랫폼(만개의레시피)도 마찬가지입니다. 공식 경로가 확인되지 않았으므로 MVP에서는 자동 수집하지 않고, 운영자가 수동으로 참고하는 신호로 강등할 것을 권장합니다.

## 데이터 파이프라인 구성도와 단계별 API 한도

```
[1. 키워드 감지 — 매일 06:00, Vercel Cron / GitHub Actions]
  NAVER API HUB 검색어 트렌드(앵커 정규화, 일 단위 8~12주) ──┐
  NAVER 검색광고 keywordstool(연관어 확장·볼륨 하한)         ├─► trend_keywords
  NAVER 블로그·카페 검색(신규 포스트 수, n-gram 후보 추출)    │    (급상승 점수: z-score + log2 WoW)
  NAVER 쇼핑인사이트(식품 카테고리 재료 교차검증)            ──┘
  (보조) Google Trends API alpha — 승인 시에만
                │
[2. 콘텐츠 탐색 — 06:30]
  YouTube search.list (≤80회/일, 급상승 키워드 + 시드, KR/ko, 최근 48h)
  YouTube playlistItems.list (화이트리스트 채널 uploads)
  (확장) IG Hashtag top_media(30태그/7일), Business Discovery
  (수동) TikTok/IG URL 등록 폼 ──► content_candidates
                │
[3. 메트릭 갱신 — 6~24h 주기]
  YouTube videos.list / batchGetStats (50 ID/콜) ──► 내부 바이럴 점수(비노출)
  30일 TTL: 메타데이터·통계 갱신 또는 삭제
                │
[4. 레시피 구조화 — Batch]
  입력: 제목·설명란·태그만 (자막·오디오 금지)
  LLM(유료 티어, Batch API) ──► recipe JSON 초안 + n-gram 중복률 검사
                │
[5. 운영자 승인 큐] ── 사람 검수(재료·분량·알레르기, 원본 대조) ──► recipes(published)
                │
[6. 재료→상품 매칭 — 배치, 캐시]
  Phase A: 재료 사전 → 수동 생성 쿠팡 링크 / Phase B: 쿠팡 searchProducts·deeplink(subId)
  (참고) 네이버 쇼핑 검색 API — 가격대 참고, 링크 이동 아님
                │
[7. 서비스] Next.js(SSG/ISR + JSON-LD Recipe) ── 익명 리뷰(Turnstile → 사전필터 → LLM) ── Supabase
```

## "원클릭 장바구니"는 "첫 클릭 + 24시간 체크리스트"로 바꾼다

PRD 4.2의 방식 A(순차 탭 오픈, 장바구니 번들 URL)와 agent.md의 `openCoupangCartBridge`(`setTimeout`으로 `window.open` 반복)는 그대로 구현하면 안 됩니다. 장바구니 일괄 담기 공식 API는 이번 조사에서 찾지 못했습니다. 쿠팡은 사용자 상호작용 없는 강제 이동이나 리퍼러 생성을 금지합니다. **2025-10에는 '납치 광고' 파트너 10여 곳을 형사 고소했습니다** ([ZDNet Korea](https://zdnet.co.kr/view/?no=20251003142637), [클리앙](https://www.clien.net/service/board/park/18835442)). 클릭 1회에 탭 여러 개를 자동으로 여는 방식은 이 금지에 걸릴 소지가 있습니다.

그 대신 쿠팡의 24시간 트래킹을 활용합니다. 링크를 클릭한 뒤 24시간 안에 산 **다른 상품도 수익으로 인정된다는 설명이 여러 2차 출처에서 일치합니다** ([tilnote](https://tilnote.io/pages/683c144d3b88c1fc497c37f9), [choicemon](https://choicemon.com/coupang-partners-guide/)). 그러면 사용자가 첫 재료 링크 하나만 눌러도, 쿠팡 안에서 나머지 재료를 직접 담아 산 금액까지 정산됩니다. 권장 플로우는 다음 표와 같습니다.

| 순서 | 화면/동작 | 구현 포인트 |
|---|---|---|
| 1 | 레시피 상세 진입 | 재료 체크리스트 위에 대가성 문구 고정(확정형, 본문 이상 크기·대비색) |
| 2 | 보유 재료 체크 해제 | Zustand 로컬 상태, 부족 재료 N개 산출 |
| 3 | "부족 재료 장보기 목록" 모달 | 재료별 상품 카드(상품명, "가격은 쿠팡에서 확인" 또는 수집 시각 표시) |
| 4 | 재료별 [쿠팡에서 보기] 버튼 | 클릭 1회 = 탭 1개, API가 준 `link.coupang.com` 링크를 그대로 사용(자체 `/go/` 단축 금지), `subId=recipe_{id}` |
| 5 | [목록 복사/공유] | 첫 링크 클릭 뒤 쿠팡 앱에서 나머지를 검색해 담을 수 있도록 텍스트 제공 |
| 6 | 리포트 수집 | `getOrdersReport`/`getCommissionReport` 일간 배치(매일 15:00 갱신, 조회 30일 이내) ([SDK README](https://github.com/mooooburg-dev/coupang-partners-sdk-standalone/blob/master/README.md)) |

자체 도메인 리다이렉트(`/go/xxx`)는 쿠팡 정지 사유 상위의 "비공식 단축 URL"에 해당할 위험이 있습니다 ([aisum](https://aisum.com/ko/blog/coupang-partners-account-suspension-recovery-2026)). 클릭은 링크를 바꾸지 말고 클라이언트 이벤트로 별도 기록해야 합니다. AffiliateMatcher의 우선순위 중 "평점 4.5 이상·리뷰 100건 이상"과 "최저가"는 SDK README에 나온 검색 응답 필드로는 판단할 수 있는지 확인되지 않습니다. 따라서 로켓배송 여부와 운영자가 큐레이션한 재료 사전을 기준으로 단순화하는 것이 현실적입니다. 링크 생성 계층은 provider 인터페이스로 추상화해, 쿠팡 계정이 정지되더라도 다른 제휴처로 바꿀 수 있게 해 둡니다.

수익 기대치도 낮춰 잡아야 합니다. PRD 2.1은 "구매액의 3~5%"를 가정합니다. 그러나 식품 요율은 출처에 따라 **1.5%~3%**입니다 ([choicemon](https://choicemon.com/coupang-partners-income-guide/), [calcnara](https://calcnara.com/calculators/coupang-partners)). 부족 재료 3만원 주문이면 주문당 450~900원입니다. 24시간 쿠키로 5만원 장바구니가 잡혀도 750~1,500원 수준입니다. 정산은 익익월 15일이고 최소 지급액은 1만원입니다. 레시피·식재료 제휴의 국내 전환율 벤치마크는 없습니다. 이 사업은 트래픽 규모가 있어야 성립하며, 그래서 SEO가 수익 구조의 일부가 됩니다. Google 레시피 리치 결과의 필수 속성은 `name`과 `image` 두 개입니다 ([Google Recipe docs](https://developers.google.com/search/docs/appearance/structured-data/recipe)). 구조화 레시피 JSON을 JSON-LD로 그대로 내보내면 됩니다. 다만 `image`에 YouTube 썸네일을 복제해 넣는 것은 저작권과 약관을 따로 검토해야 합니다.

네이버 쇼핑 커넥트(2025-07 정식 출시)는 셀러가 수수료를 정하는 캠페인형 제휴이고 크리에이터 자격 요건이 있습니다 ([헤럴드경제](https://www.heraldk.com/article/2025072218190389988), [maily](https://maily.so/tiyou/posts/xyow3mq2r28)). 범용 식재료 링크를 자동으로 만드는 용도에는 맞지 않으므로 확장 단계의 브랜드 협업 옵션으로 둡니다.

## 법적 준수는 표시 세 가지와 게시판 절차 하나로 압축된다

월 비용(상업 운영 기준)은 다음과 같습니다. Vercel Pro는 개발자 시트당 **$20**입니다 ([Vercel Hobby](https://vercel.com/docs/plans/hobby)). Supabase Pro는 **$25부터**이고, DB 8GB·스토리지 100GB·비활성 정지 없음이 포함됩니다 ([Supabase pricing](https://supabase.com/pricing.md)). LLM은 레시피 30건/일과 후기 300건/일을 처리한다고 가정할 때 Claude Haiku 5.5나 Gemini 2.5 Flash-Lite 기준 **약 $2**, Haiku 4.5 기준 약 $19입니다 ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing), [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)). 이 추정은 자막을 포함한 입력 6k 토큰을 가정했으므로, 설명란만 입력하면 실제 비용은 더 낮습니다. 네이버 API HUB, YouTube Data API, Turnstile Free는 현재 $0입니다. 그래서 고정비는 **월 약 $47~65**입니다. 도메인 비용과 네이버 HUB 유료 전환 후 단가는 이 합계에 넣지 않았습니다. 수익 쪽에서는 주문당 수수료가 1천원 안팎이라 고정비를 넘기려면 월 수십~백 건 규모의 전환이 필요합니다. 전환율 근거가 없으므로 이 손익분기점은 런칭 후 실측해야 합니다.

## Conclusion

이번 조사로 TrendFood의 경쟁력이 어디서 나와야 하는지가 바뀌었습니다. PRD는 "많이 긁어 오는 능력"을 차별점으로 봤습니다. 그러나 2026년 한국에서 공식적으로 허용되는 데이터는 네이버 검색 신호, YouTube 하루 100회 검색, 임베드 정도로 좁습니다. 크롤링으로 이 범위를 넘어서면 API 키 회수, 제휴 계정 정지, 저작권 방조 위험이 함께 따라옵니다. 그래서 차별점은 수집량이 아니라 **선별과 검수의 질**입니다. 즉 네이버 신호로 무엇이 뜨는지 먼저 알아보고, 사람이 승인한 정확한 재료표를 제공하고, 익명 후기로 "실제로 해 보니 어땠는지"를 쌓는 것입니다. 사람 검수 단계는 비용처럼 보이지만, AI 표시 의무와 저작권 위험을 낮추고 레시피 품질을 높이는 일을 한꺼번에 해냅니다.

커머스 쪽도 같은 방향입니다. 쿠팡 장바구니를 "대신 채워 주는" 기능은 공식적으로 만들 수 없습니다. 하지만 24시간 쿠키 덕분에 "첫 클릭을 만들어 내는 장보기 목록"이면 수익 구조로 충분합니다. 다만 주문당 수수료가 1천원 안팎이므로 이 사업의 성패는 커머스 기능의 정교함보다 SEO 유입 규모에 달려 있습니다. 실행 순서는 다음과 같습니다. 출시 전에 쿠팡 15만원 승인과 법무 확인 4건(AI 표시, 사업자 신고, 국외이전, YouTube 파생 데이터)을 먼저 처리합니다. 그동안 MVP는 수동 링크와 승인 큐로 운영합니다.
